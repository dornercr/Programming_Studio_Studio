SLIDE 1: Chapter 5 — Floating-Point Representation

LECTURE NARRATION
Floating point trades exactness for a wide dynamic range. It stores a sign, a scale, and a finite set of significant bits. The consequences are systematic: nearby representable values become farther apart as magnitude grows, decimal fractions can be rounded on input, and changing operation order can change the final result. These are properties to design around, not random defects.

SLIDE 4: 5.1 Floating-Point Concepts

LECTURE NARRATION
The sign distinguishes positive and negative values. In common IEEE 754 binary formats, it is stored separately from exponent and fraction fields. Unlike two’s-complement integers, changing only the floating-point sign bit changes the sign of an ordinary finite value without changing its magnitude. The format also contains positive and negative zero. They compare equal in ordinary numerical comparison, but operations such as reciprocal can distinguish them under IEEE arithmetic. A diagnostic that prints only 0 can therefore hide a representational distinction relevant to numerical algorithms or branch-cut conventions. The exponent determines the power-of-two scale. Normal binary floating-point values have the form (-1)^s * (1.f) * 2^e . The stored exponent is biased so the field can represent both negative and positive exponents without a separate exponent sign bit. For binary32, the exponent field has eight bits and the normal-value bias is 127. A stored exponent of 130 therefore corresponds to an exponent of 3. Some exponent field values are reserved for zero, subnormal values, infinity, and NaN, so not every field pattern describes an ordinary normalized scale. The significand carries the significant digits. For a normalized binary value, the leading digit is always one, so common IEEE binary formats omit that leading one from storage. Binary32 stores 23 fraction bits but has 24 bits of normal-value precision. Binary64 stores 52 fraction bits and has 53 bits of normal-value precision. Precision is the number of significant bits, not the number of fixed decimal places. A value near one and a value near one billion do not have the same absolute spacing between representable neighbors. Numerical error requirements should therefore distinguish absolute error from relative error. [ R9 ]

SLIDE 6: 5.2 IEEE 754

LECTURE NARRATION
For binary32 with exponent field E from 1 through 254 and fraction field F , the represented value is (-1)^s * (1 + F/2^23) * 2^(E-127) . Read this as a signed significand multiplied by a power-of-two scale. Normalization gives a unique leading-one form for ordinary nonzero values. For example, binary 1101.01 becomes 1.10101 * 2^3 . The shift changes the exponent while preserving the value. Format calculations should identify the stored exponent and the mathematical exponent separately to avoid off-by-bias errors. The term subnormal is preferred for values historically called denormalized. When the exponent field is zero and the fraction is nonzero, binary32 uses (-1)^s * (F/2^23) * 2^-126 . There is no implicit leading one. This extends representable values gradually toward zero below the smallest normal magnitude. Subnormals provide gradual underflow but have fewer significant bits relative to their magnitude. Some execution modes flush tiny values to zero for particular operations. Such modes alter numerical behavior and must be treated as explicit configuration, not assumed equivalent to default IEEE-style arithmetic. An all-zero exponent field and zero fraction represent zero, with the sign field distinguishing positive and negative zero. Both compare equal, so a hash or serialization design that uses raw bits must decide whether these representations should remain distinct or be normalized. An exact zero result and a tiny result rounded to zero are not the same computational event. The latter can indicate lost information. Numerical diagnostics may need to examine exception flags or compare against a higher-precision reference rather than looking only at the final printed value. An all-one exponent field with a zero fraction represents infinity. Positive and negative infinity can arise from operations such as an overflowing finite result or division of a nonzero finite value by zero under the relevant floating-point environment. Infinity is not the largest finite number. It participates in comparison and arithmetic as a special value. An application that requires finite measurements should validate with a finite-value predicate rather than testing only that the input lies below one chosen threshold. Infinity can otherwise propagate through an algorithm and obscure the original failure. An all-one exponent field with a nonzero fraction represents a NaN, or “not a number.” NaNs represent invalid or unrepresentable numerical results such as certain indeterminate operations. In ordinary comparisons, a NaN is unequal even to itself, and ordered comparisons with it are false. Use a designated NaN predicate rather than equality to detect NaNs. Algorithms based on total ordering, minimum selection, or sorting need an explicit policy for them. A comparison function that violates the ordering requirements of a container or sorting algorithm can fail in ways unrelated to the original arithmetic.

SLIDE 8: 5.3 Floating-Point Arithmetic

LECTURE NARRATION
A format’s precision limits how many significant bits can be retained. Near 2^24 , adjacent binary32 values are two units apart. Thus the exact integer 16,777,217 cannot be represented as binary32, even though many much larger powers of two can be represented exactly. Range and precision are different. A type can hold values of enormous magnitude while failing to distinguish two nearby integers. Never use floating point as a general replacement for exact identifiers, byte counts, or unbounded integer counters. Its suitability follows from the numerical error budget of the problem. When an exact result lies between representable values, a rounding mode selects the stored result. A common default is round to nearest, ties to even: choose the nearest representable value, and choose the one with an even low significand bit when exactly halfway. Rounding occurs at operations and conversions according to the language, compiler options, and execution environment. A fused multiply-add computes a product and addition with one final rounding rather than rounding the product separately. This can improve accuracy while changing the last bits compared with two separate operations. Reproducibility requires control over such choices. A decimal fraction such as 0.1 has a repeating binary expansion, so a finite binary format stores a nearby value. Subsequent arithmetic operates on those stored approximations. Printing a short decimal representation can hide the difference; printing more digits can reveal it. Repeated addition, subtraction of nearly equal values, and changes in summation order can amplify or expose error. Use stable algorithms, appropriate precision, and tolerances tied to the problem. A fixed arbitrary epsilon is not a universal equality rule. A useful comparison often combines an absolute tolerance near zero with a relative tolerance at larger magnitudes, while treating NaNs and infinities explicitly. Floating-point overflow occurs when a result’s magnitude exceeds the format’s finite range. The result depends on the rounding mode and environment; infinity is common under round-to-nearest behavior. This is not the same rule as undefined signed integer overflow. Prevent avoidable overflow by reformulating calculations. For example, computing a Euclidean norm as sqrt(x*x + y*y) can overflow intermediate squares even when the final mathematical norm is representable. A suitable hypot implementation scales its inputs to avoid that unnecessary failure. Algorithm selection can therefore matter more than selecting a slightly wider type. Underflow concerns tiny results near zero. A result may become subnormal or round to zero. In IEEE terminology, signaling underflow is tied to tininess and inexactness rather than simply “the value is smaller than the smallest normal.” An exactly representable subnormal does not imply the same exception event as an inexact tiny result. Do not silently treat every tiny result as a defect. Some algorithms naturally produce small probabilities or residuals. The question is whether the retained information meets the application’s needs. Rescaling, logarithmic representations, or a more stable formulation may preserve useful information better than repeatedly widening every variable.

SLIDE 10: Worked example — Encoding 13.25 as binary32

LECTURE NARRATION
Start with the decimal value 13.25. The integer part 13 is binary 1101 ; the fraction 0.25 is 0.01 , so the complete binary value is 1101.01 . Normalize it to 1.10101 * 2^3 . The sign is zero. The stored exponent is 3 + 127 = 130 , or binary 10000010 . The stored fraction is 10101 followed by zeros to fill 23 positions. Its numeric field is 0x540000 . Combining sign, exponent, and fraction gives the 32-bit pattern 0x41540000 . This value is exactly representable because its binary expansion terminates within the available precision. Companion listing: ch05/float_bits.c The reference platform prints 0x41540000 . The numeric interpretation of a copied representation also assumes the reference platform’s compatible integer and float byte ordering; the format checks alone do not prove every representation detail on every machine. The example inspects a platform representation rather than defining a portable wire encoding. For a second trace, add 1 to binary32 16,777,216. The exact result lies halfway between 16,777,216 and 16,777,218. Under round-to-nearest, ties-to-even, it rounds to 16,777,216. The addition occurred, but the format could not retain that unit difference. This is precision loss, not integer-style wraparound.

SLIDE 12: Worked example — Why 0.1 is approximate

LECTURE NARRATION
Binary floating point represents fractions whose denominator is a power of two exactly. Decimal 0.1 has a repeating binary expansion, so a finite format stores the nearest representable value rather than exactly one tenth. Repeated arithmetic can therefore accumulate small errors. Equality tests on computed floating-point results should reflect the numerical problem rather than assuming decimal literals are exact.

SLIDE 14: Worked example — Classifying an IEEE 754 value

LECTURE NARRATION
For a binary32 value with exponent field all ones and a nonzero fraction, the value is NaN. With exponent all ones and fraction zero, it is infinity with the sign bit determining the sign. With exponent all zeros and fraction zero, it is signed zero. The exponent and fraction fields must be interpreted together; the exponent alone does not determine the numerical category.
