SLIDE 4: 14.1 Immediate operands

LECTURE NARRATION
An immediate operand encodes a constant in the instruction, such as $7 . It is a value, not a request to read memory at address seven. The distinction between $symbol and symbol can similarly distinguish an address-like immediate from a memory reference, subject to relocation and encoding rules. Not every instruction accepts every immediate width. Some encodings sign-extend a smaller immediate, and a full 64-bit constant may require a different encoding or instruction form. Let the assembler diagnose illegal forms, then inspect the actual encoding when code size or exact semantics matter.

SLIDE 6: 14.2 Register operands

LECTURE NARRATION
A register operand names an architectural register or subregister. movq %rdi, %rax copies the 64-bit value from %rdi to %rax . The source remains unchanged. The q suffix indicates a quadword, or 64-bit operation, in this syntax. Register moves can sometimes be handled efficiently inside a processor through renaming or other mechanisms, but they remain architectural operations. Do not assume a source-level assignment always requires a move instruction; the compiler may keep two names associated with one value or remove an unused assignment.

SLIDE 8: 14.3 Memory operands

LECTURE NARRATION
A memory operand describes an effective address. (%rdi) refers to memory at the address held in %rdi ; it does not refer to the register’s bits as the final data value. movq (%rdi), %rax loads eight bytes, while movq %rax, (%rdi) stores eight bytes. Most ordinary two-operand x86 data-processing instructions do not allow two explicit memory operands. Moving between two memory locations generally requires a register or a specialized instruction. A memory operand can fault even when its address calculation is simple, because mapping and permission checks occur separately from arithmetic validity.

SLIDE 10: 14.4 mov

LECTURE NARRATION
The mov family copies data without ordinary arithmetic transformation. Width matters: movb , movw , movl , and movq operate on 8, 16, 32, and 64 bits. The 32-bit register-destination rule zeroes the upper half of the corresponding 64-bit register. Sign-extending and zero-extending moves are separate forms. A byte loaded as unsigned into a larger register needs zero extension; a signed byte may need sign extension. A plain narrow load can leave unrelated upper bits unchanged. Always identify whether later code consumes only the narrow value or the full register.

SLIDE 12: 14.5 Addressing modes

LECTURE NARRATION
A common x86-64 memory-address form is D(B,I,S) : displacement plus base register plus index register multiplied by scale. In mathematical notation, the effective address is D + B + I*S . Missing components contribute zero or their applicable default. The addressing mode computes a byte address. The source language’s element size has already been translated into a scale or explicit arithmetic. A scale of eight is natural for an array of eight-byte elements, but a structure size of 24 may require an additional multiply or combination of additions. The hardware does not know the source-level array type.

SLIDE 14: 14.6 Displacement

LECTURE NARRATION
A displacement is a constant offset included in the address expression. 8(%rdi) accesses eight bytes beyond the address in %rdi . It can identify a structure member, a later array element, or a stack-frame location. Displacements are not automatically bounds-checked against a structure definition. The assembler sees an address expression, not the C++ object contract. When reverse-engineering generated code, relate the displacement to known member offsets and widths. A load at offset eight might be one eight-byte field or several smaller fields depending on the instruction and layout.

SLIDE 16: 14.7 Base/index addressing

LECTURE NARRATION
Base/index addressing combines a starting address with a variable position. (%rdi,%rsi) adds the two register values. If %rdi is a byte-buffer base and %rsi is a byte offset, this directly selects the desired byte position. A valid numerical addition does not prove that the resulting access stays inside an object. High-level bounds checks must precede the load or store when the index is not already trusted. Optimized assembly may move or combine checks, but the programmer’s correctness argument still needs a bounded input domain.

SLIDE 18: 14.8 Scaled indexing

LECTURE NARRATION
The standard scaled-index factor is 1, 2, 4, or 8. (%rdi,%rsi,8) is convenient for eight-byte elements. A separate displacement can select a field or shift the element index, as in 8(%rdi,%rsi,8) . For an array of 24-byte records, the compiler might compute 3*i with an lea , then use a scale of eight. Several equivalent instruction sequences can implement the same address formula. Choose the interpretation that explains the complete expression rather than assigning one source operation to each instruction mechanically.

SLIDE 20: 14.9 RIP-relative addressing

LECTURE NARRATION
RIP-relative addressing computes a location from the next instruction’s address plus a displacement. It is widely used for position-independent references to code and data within a reachable range. The assembler and linker supply relocations when the displacement cannot yet be finalized. A RIP-relative reference is not an indirect pointer lookup by itself. It computes an address relative to the instruction stream and then, for a memory instruction, accesses that address. Some dynamic-linking sequences do add another level through a table entry. Distinguish the address of a pointer slot from the pointer value stored in that slot.

SLIDE 22: 14.10 lea

LECTURE NARRATION
lea , or load effective address, computes an address-form expression and places the resulting value in a register without reading the memory at that address. It is useful for pointers and for arithmetic combinations such as x + 2*x . Unlike an ordinary add instruction, lea does not update the usual arithmetic condition flags. This can preserve a comparison result for a later branch. The name does not imply that the result must be used as a pointer; the instruction computes a numeric expression using address-generation syntax. [ R3 ]
