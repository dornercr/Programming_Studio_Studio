SLIDE 1: Chapter 13 — x86-64 Registers

LECTURE NARRATION
Register names are a vocabulary, but register use is a contract. The ISA defines what each name designates and how instructions affect it. The ABI assigns roles at function boundaries. A register used for an argument is still a general-purpose register inside a function, provided the function respects preservation and return rules.

At graduate level, do not treat this as a term to memorize. Identify the contract being described, the state or representation it constrains, and the assumptions that must remain true. SLIDE 4: 13.1 General-purpose registers

LECTURE NARRATION
The baseline x86-64 general-purpose register set includes %rax , %rbx , %rcx , %rdx , %rsi , %rdi , %rsp , %rbp , and %r8 through %r15 . They can hold integer values or addresses, with some instructions imposing implicit operand roles. The ABI distinguishes caller-saved and callee-saved registers. Caller-saved values may be overwritten by a call, so a caller must preserve any such value it needs afterward. Callee-saved registers must be restored by a function that changes them. This division reduces unnecessary saving while allowing separately compiled functions to cooperate. [ R4 ]

SLIDE 6: 13.2 Register widths

LECTURE NARRATION
A 64-bit register has narrower named views. %rax is the full 64-bit register, %eax its low 32 bits, %ax its low 16 bits, and %al its low eight bits. %ah names another eight-bit portion, but legacy high-byte registers have encoding restrictions with REX prefixes and are best avoided in beginner examples. Writing a 32-bit general-purpose register zeroes the upper 32 bits of the corresponding 64-bit register. Writing a 16-bit or eight-bit subregister generally leaves the other bits unchanged. This is why movl $1, %eax establishes a full %rax value of one, while movb $1, %al does not.

SLIDE 8: 13.3 %rax

LECTURE NARRATION
%rax commonly carries an integer or pointer return value under the System V ABI. It is caller-saved. Some multiply and divide instructions use %rax implicitly, often together with %rdx for a double-width value. Do not assume a call preserves an unrelated value in %rax ; the callee is allowed to use it for the result and temporary work. The low byte %al also has a special role when calling variadic functions under this ABI: it conveys information about vector-register arguments. Handwritten assembly that calls a variadic library routine must follow that rule rather than only loading the visible integer arguments.

SLIDE 10: 13.4 %rbx

LECTURE NARRATION
%rbx is callee-saved in the reference calling convention. A function can use it for a long-lived local value across nested calls, but must restore the caller’s original value before returning. The cost of using %rbx may include a save and restore if the function changes it. A compiler weighs that cost against repeatedly saving a caller-saved value around calls. Register allocation is therefore influenced by value lifetimes and call structure, not simply by choosing the shortest register name.

SLIDE 12: 13.5 %rcx

LECTURE NARRATION
%rcx holds the fourth ordinary integer or pointer argument in the System V convention. It is caller-saved. The low byte %cl is also the implicit count operand for traditional variable-count shift instructions. Implicit roles can constrain instruction scheduling. A compiler may need to move a shift count into %cl even when the count originally resides elsewhere. In Linux’s x86-64 system-call ABI, the fourth argument is not passed in %rcx ; the syscall interface uses %r10 for that position. Function calls and system calls must be learned as separate interfaces.

SLIDE 14: 13.6 %rdx

LECTURE NARRATION
%rdx carries the third ordinary integer or pointer argument and is caller-saved. It also participates in full-width multiplication and division. For signed 64-bit division, %rdx:%rax forms the signed double-width dividend, and the remainder is returned in %rdx . Before dividing a sign-extended 64-bit value, cqto prepares %rdx from the sign of %rax . Clearing %rdx instead is correct for certain unsigned dividends but wrong for a negative signed dividend. The register pair’s interpretation must match the chosen instruction.

SLIDE 16: 13.7 %rsi

LECTURE NARRATION
%rsi carries the second ordinary integer or pointer argument. It is caller-saved and also has a source-index role in string instructions. Inside a function it can be reused once the argument is no longer needed. A name’s historical association is not a restriction on ordinary general-purpose use. SLIDE 18: 13.8 %rdi

LECTURE NARRATION
%rdi carries the first ordinary integer or pointer argument and is caller-saved. It has a destination-index role in string instructions. In a simple function taking a pointer and a length, %rdi commonly receives the pointer and %rsi the length. The first argument can also be hidden by a language ABI rule, such as a result-storage pointer or a C++ object pointer in particular cases. SLIDE 20: 13.9 %rsp

LECTURE NARRATION
%rsp is the stack pointer. Push, pop, call, and return operations use it according to their instruction semantics. The ABI requires suitable alignment at call boundaries and restoration of the caller’s stack position before a normal return. Corrupting %rsp can redirect subsequent stack accesses and returns. Handwritten assembly must account for every push, pop, and explicit adjustment. A balanced count alone is not enough if the adjustments occur on only some control-flow paths. Trace the stack depth along every path to the return instruction.

SLIDE 22: 13.10 %rbp

LECTURE NARRATION
%rbp is callee-saved and can serve as a frame pointer. A conventional prologue saves the old value and makes %rbp a stable reference point for the current frame. Optimized code often omits this dedicated role and uses the register for other purposes. The absence of %rbp -based accesses does not mean a function lacks local state or cannot be unwound. Debugging and exception unwinding can use metadata that describes stack changes. Conversely, having a frame pointer does not make corrupted stack contents trustworthy.

SLIDE 24: 13.11 %r8–%r15

LECTURE NARRATION
%r8 and %r9 carry the fifth and sixth ordinary integer or pointer arguments. %r10 and %r11 are caller-saved temporaries. %r12 through %r15 are callee-saved. The narrower forms use suffixes such as %r8d , %r8w , and %r8b . These registers expand the available working set and reduce some memory spills compared with a smaller register set. They do not eliminate register pressure. Large expressions, vector work, and many simultaneously live values can still require spills to stack storage. A spill is a consequence of allocation constraints, not necessarily a sign of an incompetent compiler.

SLIDE 26: 13.12 Instruction pointer

LECTURE NARRATION
%rip identifies the instruction stream position. It is not manipulated as an ordinary general-purpose destination in the same way as %rax ; control-transfer instructions and relative-addressing mechanisms provide the relevant operations. RIP-relative addressing supports position-independent access to nearby code and data. The code can refer to a symbol using a displacement that remains useful when the image is relocated. Relocations and linker decisions still matter, especially for symbols outside the current image or with different visibility.

SLIDE 28: 13.13 Condition flags

LECTURE NARRATION
The flags register includes status bits such as zero, sign, carry, and overflow. Arithmetic and comparison instructions update selected flags. Conditional branches, conditional moves, and set-on-condition instructions then interpret them. Flags do not have one universal “comparison result” meaning. Signed and unsigned order use different combinations. Carry is relevant to unsigned overflow or borrow interpretation; overflow describes signed-range overflow for particular arithmetic operations. An intervening instruction can overwrite flags, so keep the producing instruction and consuming branch connected in the data-flow analysis. [ R3 ]
