SLIDE 6: 32.2 Prefetching

LECTURE NARRATION
Prefetching requests data before demand needs it. Hardware may recognize access patterns; software can sometimes provide explicit hints. Effective prefetching hides latency when requests arrive early enough and the data remains useful until consumption. Prefetching too early can evict useful data. Prefetching too much wastes bandwidth and cache capacity. It also cannot remove a true dependency that prevents the future address from being known. Start with an access pattern that naturally exposes locality before adding architecture-specific hints.

At graduate level, do not treat this as a term to memorize. Identify the contract being described, the state or representation it constrains, and the assumptions that must remain true. SLIDE 8: 32.3 Batching

LECTURE NARRATION
Batching groups work so that setup and transfer costs are shared. Processing several records together can reuse metadata, amortize system calls, and expose independent memory operations. It can also increase latency for an individual record waiting for the batch to fill. Bound batch size by both resource capacity and service requirements. An unbounded batch can grow the working set beyond cache, delay cancellation, and exhaust memory. A useful batch is large enough to amortize overhead but small enough to preserve locality and responsiveness.

SLIDE 10: 32.4 Write coalescing

LECTURE NARRATION
Write coalescing combines nearby or repeated updates into fewer larger transfers. Updating several fields while a line is already present can avoid repeatedly acquiring and evicting it. Buffered file output similarly groups small writes before crossing the kernel boundary. Coalescing changes visibility and durability timing when buffering is involved. A program must still honor synchronization and persistence requirements. Do not delay a required publication or commit merely because a larger batch would be faster.

SLIDE 12: 32.5 Cache-friendly data structures

LECTURE NARRATION
A cache-friendly structure places information used together close together and avoids loading large amounts of irrelevant state. Arrays often provide compact traversal. Pointer-rich structures provide flexible updates but can add indirection, allocation overhead, and unpredictable access. An array of structures is convenient when most fields of each record are used together. A structure of arrays can be better when a loop uses only one field across many records. Neither layout is universally superior. Let the hot operations determine which bytes should travel together.

SLIDE 14: 32.6 Cache-friendly loops

LECTURE NARRATION
Cache-friendly loops traverse data in an order that preserves spatial and temporal reuse. Loop interchange can align traversal with physical layout. Blocking limits the active region. Hoisting invariant work reduces repeated computation and sometimes repeated loads. Transformations must preserve dependencies and language semantics. Reordering floating-point reductions can change results; reordering updates can break an algorithm with cross-iteration dependencies. Establish correctness constraints before treating the iteration space as freely rearrangeable.

SLIDE 16: 32.7 Locality optimization

LECTURE NARRATION
Locality optimization is a sequence: identify the hot phase, estimate its active data, inspect access order, propose a change, verify results, and measure under controlled conditions. Keep a baseline so that an appealing theory can be rejected when the data does not support it. Avoid changing several unrelated factors at once. Replacing a linked structure, changing allocation strategy, and altering the algorithm simultaneously makes it difficult to determine which change helped. A sequence of tested transformations produces more reliable conclusions and easier rollback.

SLIDE 18: Worked example — A two-level AMAT calculation

LECTURE NARRATION
Assume an L1 hit time of 1 ns, an L1 miss rate of 5%, an L2 access time of 8 ns on L1 misses, an L2 local miss rate of 20%, and an additional memory penalty of 80 ns after an L2 miss. These are illustrative values , not measurements of a named processor. Now suppose a layout change reduces the L1 miss rate to 3% without changing other parameters. The modeled AMAT becomes 1 + 0.03 × 24 = 1.72 ns , a reduction of about 21.8% in this modeled access cost. It would be incorrect to promise a 21.8% whole-program speedup. If these accesses account for only half the original execution time and all other time remains unchanged, the new normalized time is 0.5 + 0.5*(1.72/2.2) , approximately 0.891. The implied speedup is about 1.122, or 12.2%, under those additional assumptions. Chapter 56 generalizes this reasoning with Amdahl’s law.

SLIDE 20: Worked example — Average memory-access time

LECTURE NARRATION
If L1 hit time is 1 ns, miss rate is 5%, and miss penalty is 40 ns, a simple AMAT model is 1 + 0.05 × 40 = 3 ns . Reducing miss rate to 2% yields 1 + 0.02 × 40 = 1.8 ns . A small miss-rate change matters because the penalty is large relative to hit time.

SLIDE 22: Worked example — Loop interchange for locality

LECTURE NARRATION
For a row-major 2D array, iterating columns inside rows accesses adjacent elements; iterating rows inside columns jumps by an entire row between accesses. Exchanging the loops can turn strided access into sequential access while preserving the mathematical operation when dependencies allow it.
