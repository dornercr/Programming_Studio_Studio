# 1
A new JSON record needs the same validation and stored prefix. Which two types change?|Add a Record implementation and an ArchiveJob creator that returns it. Keep ArchiveJob::run unchanged so every format still passes the same input gate and prefix step.
Why is returning a pointer to a local Record from make unsafe?|The local object dies when make returns. Its address would dangle before run calls format. Return an owning unique_ptr to a separately allocated product instead.
Would a switch be simpler for two formats that will never grow?|Yes. A small fixed choice may need only a function and a switch. Factory Method pays for a changing family of creators or a framework-controlled workflow, not for every construction call.
Does const on ArchiveJob::run mean no allocation occurs?|No. It prevents ordinary mutation of that job through this method. The method may create and destroy a separate Record, and allocation can still fail.
What must a counting mock creator observe for empty input?|Zero calls to make. The text gate runs first. This tests workflow order, which matching one successful output cannot prove.
Can replacing unique_ptr with shared_ptr fix a null product?|No. Both smart pointers can be empty. The contract check is still required; shared ownership would change lifetime policy without repairing a missing product.
Why retain the EmptyJob negative test when all current real creators are correct?|A future creator can violate the nonnull rule. The test keeps the framework boundary explicit and prevents a later unchecked dereference.
# 2
Two encoders emit identical bytes today. Must their decoders be interchangeable forever?|No. Matching a few outputs does not establish the whole protocol contract. Test the complete supported input domain and malformed inputs before claiming interchangeability.
Where should a client choose the codec family for one session?|Choose one factory at the session boundary and obtain both products from it. Choosing each product independently makes accidental mixed families easier.
Would one encode/decode object be simpler than two product interfaces?|Yes, if clients always need both together and neither varies independently. Abstract Factory is useful when several related products must be supplied through separate roles.
Why test all ten digits instead of only seven?|The domain is tiny, so exhaustive valid-input checks are cheap. They catch endpoint and off-by-one defects that a single demonstration misses.
Does a unique_ptr<Decoder> express protocol compatibility?|No. It expresses ownership and the Decoder interface. Family compatibility remains a design rule enforced by factory construction and tests.
What should happen to d=04 in this chapter's protocol?|Reject it. The supported tagged form has exactly one digit, so accepting an extra zero silently broadens the language beyond the stated contract.
How can a new family be added without editing round_trip?|Implement matching Encoder and Decoder products plus a CodecFactory. round_trip depends on those interfaces and checks that decoding recovers the original digit.
# 3
Why does build return a Plan value instead of a reference to the draft?|The finished plan must survive later draft edits and reset. Returning a reference would tie the result to mutable builder storage and make old plans change unexpectedly.
Should add reject a draft total above ninety immediately in this implementation?|The delivered builder checks each session during add and the combined total during build. Moving the total check changes when failure occurs, so callers and tests must agree on that revised contract.
Is resetting a builder the same as destroying a finished Plan?|No. Reset clears only draft state. Finished Plan values own their title and durations independently.
When would a plain Plan constructor be preferable?|When all required values are known together and construction has few choices. A builder helps when a valid result needs several ordered or named steps and drafts may be incomplete.
Why can named return PlanBuilder& safely here?|It returns a reference to the same live builder, allowing chained calls. The reference must not be retained after that builder dies.
What test detects accidental accumulation across reset?|Build an old draft, reset, then build a new seven-minute plan. Assert the new total is seven and the old Plan still has its original total.
Why is a director optional rather than another required object?|A director is simply a reusable recipe. introduction is a function that performs such a recipe; a separate director class adds little when no state or multiple operations are needed.
# 4
Why is copying a unique_ptr member not a valid deep-copy implementation?|unique_ptr deliberately forbids copying ownership. The copy constructor must allocate a new string and copy the string value, giving each object its own release responsibility.
Can clone return the same object under a new unique_ptr?|No. Two independent unique_ptr owners of one address would both delete it. A clone must be a distinct owned object under this contract.
Why test destruction of the original before using the clone?|It checks independence of lifetime, not just equality of text. A shallow borrow may appear correct until the original goes away.
Would a copied shared_ptr meet the independent-edit contract?|Not by itself. It would share one mutable object, so edits could leak between copies. Immutable sharing or copy-on-write would need an explicitly different design.
What does copying through Cue& preserve that slicing Cue by value would lose?|Virtual clone selects the actual concrete kind. Base-value copying would not preserve derived state, and this abstract Cue cannot be instantiated as a value at all.
Which part of ListCue makes its default copy sufficient?|vector<string> owns its elements as values. Copying it copies the strings; there are no borrowed element pointers that require a separate deep-copy loop.
When is Prototype unnecessary?|When callers know the concrete type and ordinary value copying already expresses the requirement. Prototype helps copy through a common interface without naming every concrete kind.
# 5
Does safe construction of a local static make every operation thread-safe?|No. C++ protects the one-time initialization. Ticket counter updates still require their own lock, which LocalTickets::take holds across checking and incrementing.
Why does the test use LocalTickets instead of resetting the singleton?|A local instance gives each test fresh state without a global reset hook. Resetting a shared service can interfere with other clients and hide order-dependent tests.
Does one singleton imply one dispenser across several processes?|No. This object lives within a process. Separate processes have separate memory; a cross-process ticket service needs another coordination mechanism.
Why should admit accept TicketSource& rather than fetch the global instance itself?|The dependency becomes visible and replaceable. Production can pass the singleton while tests or independent sessions pass local sources.
What is wrong with unlocking between checking the limit and incrementing?|Two threads could both pass the same check before either advances the counter. Keep the state transition within one lock scope.
When would a normal owned service be clearer than a singleton?|When lifetime, configuration, or independent sessions matter. One application-owned object passed to clients often gives uniqueness without hidden global access.
Why can test execution order expose a hidden singleton dependency?|A prior test may consume tickets. A later test then sees an exhausted global source even though its own local setup is fresh; that is shared state leaking across test boundaries.
# 6
Why is a reference member not proof that the scale owns its device?|A reference is a borrow. The LegacyScale must outlive ScaleAdapter; destroying the device first leaves the adapter with an invalid reference.
Would renaming milligrams to grams be a correct adapter?|No. The units differ by a factor of one thousand. Interface compatibility includes meaning and error behavior, not only method names.
Why subtract calibration after conversion in this example?|The offset is measured in grams. Subtracting it from raw milligrams would mix units and produce a numerically plausible but wrong result.
When can the adapter be a free function instead of a class?|When the caller needs one conversion and no persistent Scale interface or borrowed device. A class is useful when existing client code already consumes Scale polymorphically.
What additional test is needed if floating readings replace integer milligrams?|Test nonfinite values and rounding near boundaries. The current integer device cannot produce NaN, but a new floating device can.
Does a valid converted value prove the device reading was valid?|No. A negative device error might become plausible after careless arithmetic. Validate the raw error signal before converting or calibrating.
Why keep light_enough independent of LegacyScale?|Its rule is about grams and a Scale contract. Keeping the old device API outside the client makes replacement devices easier to integrate and test.
# 7
Why are CountCsv and WarningCsv subclasses unnecessary?|The report supplies meaning and delegates representation to Writer. Csv can be paired with both existing report types without multiplying combined subclasses.
What lifetime condition must hold for a Report constructed from a Writer reference?|The writer must remain alive for every report call. Constructing a report from a temporary writer and retaining it would leave a dangling borrow.
Is Bridge the same as converting milligrams to grams?|No. Adapter repairs a mismatch with an existing interface. This Bridge separates report meaning from formatting so both dimensions can grow independently.
Where should a new warning threshold be implemented?|In report policy, not Csv or Brackets. Writers receive an already chosen label and number and should not decide when a count is high.
Would a function parameter for formatting be simpler?|Often yes, if the behavior is small and the report does not need a persistent polymorphic interface. Bridge describes the separation, not a requirement to maximize classes.
Why test one writer with two report kinds?|It checks that the new representation composes with existing meanings. Testing only one combination may miss a hard-coded label or special case.
Does sharing a const Writer reference guarantee thread safety?|No general guarantee follows from const alone. A concrete writer could use mutable state or external resources; its implementation must supply any concurrency guarantee.
# 8
Why is an empty Group valid while a null child is invalid?|An empty group has a well-defined sum of zero. A null entry claims a child position without an object on which minutes or steps can be called.
Why does Group own children with unique_ptr rather than borrow them?|The tree controls child lifetime. Removing or destroying an owning group recursively destroys its descendants without requiring callers to track each child separately.
What change would sharing one child between two parents require?|A different ownership model and a clear counting rule. Shared ownership might keep the child alive, but it would not decide whether the shared work should be counted once or twice.
Why check n against 10000 minus total before adding?|The design rejects an over-budget sum before accepting the new total. Checking only after arbitrary signed addition is unsafe in more general unbounded versions.
Could a single struct with a variant replace the virtual Work hierarchy?|Yes. A closed set of node kinds may be clearer as values with a tagged alternative. The interface hierarchy is useful when new kinds must be added separately.
Why are minutes and steps different operations on the same tree?|Minutes measures duration; steps counts leaves. A zero-minute leaf contributes zero to one and one to the other, exposing assumptions hidden by ordinary positive examples.
What test detects accidentally counting groups as steps?|Nest an empty group and a one-leaf group inside a parent. The leaf count should be one, regardless of the number of internal groups.
# 9
Why does reversing two wrappers often change the result?|Each wrapper receives the result of its inner object. Limiting before adding text differs from limiting after adding it, so the composition is generally order-sensitive.
Does Decorator require every wrapper to add characters?|No. Limit removes characters while keeping the Message interface. The common property is wrapping an object and changing behavior, not always increasing output size.
Why are wrapper service objects nonmovable while their unique_ptr handles can move?|Moving the handle transfers ownership without relocating the service object. This preserves object identity and avoids supporting partially moved service states.
Could one formatting function replace this wrapper graph?|Yes for a small fixed pipeline. Wrappers earn their cost when callers assemble and reorder optional behavior through a shared interface.
Why should a null-inner check run during construction?|It prevents creating a wrapper that can never satisfy text(). Detecting the error at assembly time is clearer than crashing during a later render.
How would byte limits differ from display-character limits?|std::string::substr counts bytes. A UTF-8 character can use several bytes, so a byte cut may split it. A display-text contract needs a suitable text-aware representation.
What ownership action happens when the outermost wrapper is destroyed?|Its unique_ptr destroys the inner object, which destroys its own inner object in turn. Virtual destructors allow deletion through Message to reach the actual types.
# 10
Why is accepting the prefix of 7x a parsing bug rather than a range bug?|Seven is in range, but the complete token is not an integer. Syntax validation must establish full consumption before numeric range validation is meaningful.
Does a Facade forbid clients from using subsystem classes directly?|No. It offers a simpler supported route. Direct calls may be useful but must respect the subsystem preconditions, such as validating values before summarizing.
Why is mean implemented through run rather than duplicating parsing?|run already coordinates syntax, count and range checks. Reusing it keeps a new operation from silently accepting inputs that the old operation rejects.
What prevents total overflow under this example's stated bounds?|At most one thousand values each lie between minus one hundred and one hundred. The total magnitude is at most one hundred thousand, which fits the required int implementation used here.
What test should accompany an increased input-count limit?|Recheck arithmetic bounds and memory behavior, not only the new count boundary. A previously safe accumulator may become unsafe when the accepted domain grows.
Would a single import function be an acceptable facade?|Yes. A facade is an easier entry point over coordinated operations; it need not be a stateful class when a function expresses that job clearly.
Why can a successful mean test miss malformed-token bugs?|An ordinary numeric string never exercises the parser's end pointer. Test junk suffixes and fractional tokens separately from arithmetic results.
# 11
Why does the pool key exclude a Mark's position?|Position differs for each use, so including it would prevent useful style sharing. Name and size define the intrinsic shared value; position remains local.
Can clearing the pool guarantee immediate destruction of every style?|No. Marks may still own shared references. Clearing drops only the pool's ownership, and each style dies when its last owner releases it.
Why is shared_ptr<const Style> preferable to shared_ptr<Style> here?|Clients should not mutate a style shared by many marks. The const target blocks ordinary mutation through those handles and protects the meaning of the pool key.
Does an equal style value imply an equal pointer after clear?|No. A new allocation can hold the same name and size. Value equality and identity are different questions, especially across pool generations.
When is Flyweight a poor tradeoff?|When there are few repetitions or small cheap values. Maps, pointers and allocation overhead can cost more than storing the data directly; measure the actual workload.
Why does std::move(left) still leave this Mark usable in the supplied program?|Mark declares copy operations and no move constructor. The rvalue binds to its copy constructor, which copies the shared pointer and position; std::move alone does not perform a move.
What should a memory test measure besides pool.count()?|Count retained styles and client references over time. A small current pool does not imply little live memory if old marks keep earlier styles alive.
# 12

What is the difference between unloaded and uncached here?|Unloaded means no RealHours object exists. Uncached means no remembered opening value exists. Invalidation can clear the value while retaining the already constructed service.
Why use optional<int> instead of zero as the empty-cache marker?|Midnight is a valid zero opening hour. optional represents absence separately from all valid integer values.
Does caching promise that opening always returns current source data?|No. This proxy explicitly allows staleness until invalidate or refresh. Freshness is part of the contract and must be clear to callers.
When would direct access be simpler than this proxy?|When source reads are cheap and no caching, delayed construction or access control is needed. An extra proxy then adds state without solving a real problem.
Why does a denied refresh leave the old cache intact?|Permission is tested before invalidation. A rejected request must not change the cache or perform a source read under this contract.
What lifetime issue is not solved by owning RealHours?|Both the proxy and real service borrow Source. Owning the service does not extend the source's lifetime; the caller must keep Source alive.

Why does an empty optional differ from an empty string reply?|An empty optional means decline and continue. A present empty string is still a reply and stops the chain, so the representation separates absence from reply content.
Why put page validation before the handler loop?|The input rule applies to all destinations. Without one shared gate, an early permissive rule might accept a request that later rules would reject.
When would a map from format to handler be simpler?|When formats are distinct keys with no overlap or priority. A chain is useful when multiple rules can match and ordered choice is intentional.
What regression test should accompany inserting a broad handler near the front?|Check requests previously handled by later specific rules. A broad match can shadow them even when its own isolated tests pass.
Does this chain call every accepting handler?|No. It returns at the first present Reply. A broadcast pipeline is a different contract and needs different control flow and tests.
Why is a vector of functions sufficient for this example?|Each rule has one operation and needs no exposed object state. A class hierarchy would add machinery without improving this small callable contract.
What should happen if a Rule itself throws?|The supplied route does not catch it, so the exception propagates and later handlers do not run. Continuing after failure would require an explicit error policy.
# 14

Does run_batch roll back every possible exception?|No. It catches out_of_range only and assumes undo succeeds for its intended Move commands. A general transaction system needs policies for other failures and failed undo.
Why does constructing Move leave Marker unchanged?|A Command represents a request before executing it. Separating creation from execution allows queuing and inspection without immediate side effects.

Could a lambda replace Command for a fire-and-forget action?|Yes. The interface is useful when the caller needs shared operations such as execute and undo. A single callable can be simpler when undo and stored status are unnecessary.
What additional test is needed for a batch starting from position one?|Fail after two successful moves and assert rollback reaches one, not zero. This catches implementations that reset to a hard-coded default instead of restoring history.
# 15
Why copy the current element out of Cursor::read?|The caller receives an int value rather than a reference into vector storage. A later append cannot invalidate that copied number, though it invalidates the cursor.
Does the version stamp keep a destroyed Readings owner alive?|No. It detects mutations only while the borrowed owner is alive. Using a cursor after owner destruction is still invalid.
Why validate done as well as read?|A stale cursor must not silently appear finished or unfinished against a changed collection. Every operation that observes traversal state must respect invalidation.
Would standard vector iterators be preferable in ordinary code?|Usually, if their invalidation rules satisfy the requirement. This custom cursor adds a checked version contract for teaching and for clients needing explicit stale-view errors.
Why check version exhaustion before appending?|The version must never wrap to an old value and falsely validate a stale cursor. The check prevents mutation when no fresh stamp is available.
What does independent position mean when two cursors share one owner?|They read the same collection but track separate indices. Advancing one cursor must not advance the other; appending to the owner invalidates both.
Why use remaining minus one for reverse read?|remaining counts unread elements. For a nonempty view, the next reverse index is one less than that count; checking empty first prevents unsigned underflow.
# 16
Why does NameField report a change instead of directly enabling SaveButton?|The field knows its value but not the complete form policy. Form combines name, consent and hold in one place, preventing inconsistent partial decisions.
Why are silent button updates important?|If enabling the button emitted another change that repeated coordination, it could form a feedback loop. The mediator updates derived state without recursively notifying itself.

What invariant should a table-driven test cover?|For all combinations, enabled equals nonempty name AND accepted consent AND no hold. Testing the truth table catches accidentally dropped conditions.

# 17
Why does History store snapshots instead of accessing Selection's private fields?|Selection owns the rule for creating valid saved state. History can keep and return opaque values without learning or duplicating that internal representation.
Is this snapshot tied to the identity of one Selection object?|No. It holds a valid interval pair and can restore another Selection. An identity-bound snapshot would need a different contract and checks.
Why copy the history before eviction and insertion?|If allocation fails while building the proposed history, the original history remains unchanged. Evicting first would lose an entry before the new one was safely stored.
What happens when undo succeeds?|The most recent snapshot restores the selection, then that history entry is removed. A second undo moves to an older entry rather than repeating the same restore forever.
When can saving a whole object be too expensive?|When state is very large or changes frequently. Deltas, persistent structures or explicit commands may reduce storage, at the cost of more complex restore behavior.
What distinguishes Memento from Command undo in these chapters?|Memento restores saved state. Command remembers an operation and enough information to reverse it. Both can support undo but store different kinds of history.

# 18
Does a throwing listener undo earlier deliveries?|No. Total changes its sum before its hook, and earlier listeners may already have run. The exception stops later delivery but does not roll back completed effects.
Why store weak_ptr registrations instead of shared_ptr registrations?|The feed does not own listener lifetime. A client can release its listener without a permanent feed reference keeping it alive.
What keeps a listener alive during one update call?|Locking its weak_ptr produces a temporary shared_ptr. That temporary keeps the listener alive for the call even if other owners release it meanwhile.
How does the older snapshot-policy lab differ from Feed?|The snapshot lab copies its listener list before dispatch. Feed instead rejects registration changes during dispatch. These are alternative policies, not conflicting guarantees of Observer itself.
Why forbid nested publish in this Feed?|Nested delivery can create unexpected order and recursive calls. This example chooses a simple nonreentrant contract and reports the attempt instead of pretending to support it.
What must a cleanup guard restore after callback failure?|The notifying flag. Without scope-based cleanup, one exception would leave the feed permanently busy even though no delivery is active.
Does weak_ptr make concurrent subscribe and publish safe?|No. It manages lifetime, not unsynchronized access to the registration vector and flag. This example does not provide a multithreaded publication contract.
