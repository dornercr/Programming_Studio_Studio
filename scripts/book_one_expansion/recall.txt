# Chapter | Question | Explained answer. These are original teaching cards.
1|What changes when you save main.cpp?|Only source text on disk changes. An executable changes after a successful build. Run the newly built file to check the change.
1|What job does preprocessing do?|It handles directives such as #include and conditional compilation before later translation stages. Included declarations become part of the translation unit.
1|What does a compiler check that an editor may miss?|It checks actual code under the selected language mode, including types and declarations. Syntax coloring is not proof that a build succeeds.
1|What is an object file missing before linking?|It may still have references to definitions in other object files or libraries. Linking resolves those references and combines the required pieces.
1|A source file compiles, but add() is undefined at link time. Where should you look?|Look for the missing definition, a signature mismatch, or an object file omitted from the link command. Rewriting the caller's arithmetic will not supply the missing symbol.
1|Why can an old executable print output after a failed build?|A failed build may leave the previous executable in place. Its output describes the previous successful build, not the changed source.
1|What does -std=c++20 select?|It selects a compiler's C++20 language mode. Compiler and standard-library support must still be checked for features you actually use.
1|Does __cplusplus identify the operating system?|No. It reports a language-version tag. It does not describe the operating system, processor, or every supported library feature.
1|How do compilation and execution differ?|Compilation translates and checks source. Execution runs the resulting program on input. A valid translation can still contain a wrong algorithm.
1|Why keep a reading's identifier and value in one record when sorting?|Moving the record keeps those fields together. Sorting a separate identifier array can attach measurements to the wrong identifiers.
1|What must a sort comparison using integer identifiers promise?|It must define a strict weak ordering. Using < works for these identifiers; using <= incorrectly says a value precedes itself.
1|What evidence connects observed output to a particular source change?|Record the source revision, exact build command, successful exit status, executable path, input, and output. Each item closes a different gap in the evidence trail.
2|Why does installing a code editor not finish C++ setup?|The editor may not include a compiler, headers, or linker. Build a small program with the actual tools to verify the environment.
2|What does PATH affect when you type g++?|It helps the shell choose an executable named g++. Multiple installed compilers can make the chosen version differ from the one you expected.
2|Why record both the compiler path and its version?|The version describes a tool; the path identifies which installation ran. Two terminals can find different installations even on one computer.
2|What is the purpose of -Wall and -Wextra?|They enable useful warning groups. Warnings can expose likely mistakes, but enabling them does not prove that all defects will be detected.
2|What does -g add to a build?|Debug information helps a debugger connect machine instructions to source and inspect program state. It does not make wrong code correct.
2|What does -c change in a compiler command?|It requests compilation to an object file without the final link step. A later command must link the needed objects into an executable.
2|Why should each source file be built with the intended language mode?|Each file is translated separately. A flag on one compilation does not retroactively change how another object file was built.
2|The terminal builds correctly, but the IDE fails. What should you compare?|Compare compiler path, working directory, language flags, include paths, linked files, and environment. The front end may be invoking a different command.
2|Why is a clean-directory build a useful setup test?|It reduces accidental help from stale objects, local settings, and old executables. The recorded instructions must supply what the build really needs.
2|Does a successful empty main() verify all project dependencies?|No. It verifies only the tools and features that test used. A probe must include and use the dependencies the real project requires.
2|Why distinguish debug and release builds?|They may use different optimization and diagnostic settings. Keep the configurations explicit so you know which behavior and evidence you are examining.
2|What belongs in a reproducible environment fingerprint?|Compiler identity, version, language mode, relevant flags, library assumptions, platform facts, and exact commands. Record measured facts rather than editor labels.
3|What does main() do in a hosted C++ program?|It is the program's required entry function. Startup work happens before it; execution of your main body begins when the runtime calls it.
3|What does return 0 from main() tell the environment?|It signals successful termination. A program can still report a wrong answer while returning zero, so tests must also check output and state.
3|What does the semicolon in int count = 3; mark?|It ends the declaration statement. Braces group statements; a semicolon does not replace a missing closing brace.
3|What does std:: mean in std::cout?|The :: operator selects a name in a scope. Here it selects cout from the standard-library namespace std.
3|What does << do in std::cout << count?|For this stream it inserts a formatted value into output. The same symbol has other meanings for other operand types.
3|Why can several stream insertions be chained?|An insertion returns the stream, so the next << uses that same stream. Values are inserted from the chain's left toward its right.
3|What is the difference between '\n' and std::endl?|Both produce a newline in this use. std::endl also flushes the stream; an ordinary newline avoids requiring that flush.
3|Why test if (std::cin >> count) before using count?|The condition checks whether extraction succeeded. An initialized variable alone does not prove that fresh input was read.
3|Does reading a number prove it meets the application's rules?|No. Extraction checks representation; domain validation checks rules such as an allowed range. Both boundaries need tests.
3|Why can invalid input stop later extractions?|The stream records failure. Recovery may require clearing that state and removing the offending input; repeating the same read alone does not solve the problem.
3|Why test with redirected input as well as typing?|A saved input file makes the session repeatable. It can include end-of-file and malformed cases that are easy to miss during a friendly interactive run.
3|What should a complete input test matrix include?|Valid values, both boundaries, out-of-range numbers, malformed text, empty input, and unexpected trailing material when the format forbids it.
4|How do initialization and assignment differ?|Initialization gives a new object its starting value. Assignment changes an object that already exists. Mixing the two can hide an invalid starting state.
4|Why initialize a local fundamental-type variable before reading it?|An uninitialized local int does not provide a usable known value. Explicit initialization establishes a state; successful input must still be checked separately.
4|Why can int count{2.5}; be rejected?|List initialization rejects this narrowing conversion. It prevents silently discarding the fractional part at that initialization boundary.
4|What does auto infer from auto total = 7;?|It infers int from the initializer. auto does not mean that total can change to a different type later.
4|Does auto ratio = 7 / 2; infer a fractional result?|No. Integer division happens with int operands, so the result is int with value 3. Type inference does not repair the calculation.
4|Why use std::numeric_limits rather than assume every int has the same bounds?|The implementation defines type ranges within standard rules. numeric_limits lets the program inspect the actual type properties it relies on.
4|What happens when unsigned arithmetic passes its maximum?|It wraps modulo the type's range. This is defined arithmetic, but it may violate a count or size requirement.
4|Why is signed integer overflow a serious defect?|Its behavior is undefined. Do not predict a portable wrapped result; check bounds or choose a suitable representation before the operation.
4|Why can 0.1 be an approximation in floating-point storage?|A finite binary representation cannot express every decimal fraction exactly. Rounding can affect calculations and equality comparisons.
4|What does const promise for a variable?|The program cannot modify that object through its const-qualified access. const alone does not mean the value is known during compilation.
4|What does constexpr add for a variable?|Its initializer must satisfy constant-expression rules. It supports uses requiring compile-time values, such as suitable fixed array bounds.
4|Why does a cast not validate a numeric value?|A cast requests a conversion. It does not prove the source fits the destination or meets the domain's rules. Check the required facts before converting.
5|What are 17 / 5 and 17 % 5 with int operands?|They are 3 and 2. Three complete groups consume 15 items, leaving two. Quotient and remainder describe different parts of the same division.
5|What are -7 / 3 and -7 % 3 in modern C++?|They are -2 and -1. Integer division truncates toward zero, and the remainder keeps the dividend's sign when it is nonzero.
5|Why does double average = 5 / 2; produce 2.0?|The int operands divide first, producing 2. Only then is that result converted to double. Convert an operand before division to obtain 2.5.
5|How do = and == differ?|= assigns a value. == compares values and produces a Boolean result. A valid assignment inside a condition can still be a logic bug.
5|Why is 0 <= x <= 10 not a C++ range test?|The first comparison produces true or false, which the next comparison treats as 1 or 0. Use x >= 0 && x <= 10.
5|What does short-circuit evaluation of && guarantee?|If the left operand is false, the right operand is not evaluated. Put a needed safety check on the left, such as a nonzero divisor.
5|What does short-circuit evaluation of || guarantee?|If the left operand is true, the right operand is not evaluated. This is useful when the first check already decides the result.
5|Does multiplication's precedence tell you which function argument runs first?|No. Precedence groups an expression; evaluation-order rules determine when its parts run. Separate side effects when their order matters.
5|Why can casting after a multiplication be too late?|The multiplication occurs in its operands' type before the cast. If that operation overflows, converting its result afterward cannot repair it.
5|What does ++count change?|It increments count and produces the updated value. count++ also increments but produces the previous value for that expression.
5|Why use parentheses around a compound arithmetic intention?|They make the grouping clear to readers. They help prevent a maintenance edit from silently changing how the formula is grouped.
5|What invariant checks a packing calculation?|For valid nonnegative items and a positive group size, items equals quotient times size plus remainder, with remainder from zero through size minus one.
6|When does an if body run?|It runs when its condition converts to true. A false condition skips that body and may select an associated else branch.
6|How does an else-if chain differ from separate if statements?|The chain selects the first matching branch. Separate if statements may all run, so overlapping conditions can perform multiple actions.
6|Why should threshold tests be ordered carefully?|A broad early condition can catch values intended for a later specific condition. Write the boundary table before choosing branch order.
6|What does an else bind to in nested conditionals?|It binds to the nearest unmatched if allowed by the grammar. Braces show your intended grouping and avoid misleading indentation.
6|Why can if (ready); cause an unexpected action?|The semicolon forms an empty statement as the if body. A following block runs independently of the condition.
6|What does break usually do inside a switch?|It ends the switch statement. Without it, execution may continue into later case statements even when their labels did not match the input.
6|What does [[fallthrough]] communicate?|It marks intentional fallthrough between switch cases. It documents intent and can suppress related warnings; it does not itself transfer control.
6|Why add a default case to a menu switch?|It handles choices not named by the cases. Define the response instead of letting an invalid command silently appear successful.
6|What is a guard clause?|It checks a blocking condition and returns early. It can make the main successful path easier to follow by reducing nesting.
6|How can named predicates improve a condition?|Names such as paid and addressValid expose the rule. The expression still needs correct operators and a documented priority when several checks fail.
6|What values best expose an off-by-one threshold bug?|Test one below the threshold, the threshold itself, and one above. Those three values show which branch owns the boundary.
6|Why inspect state after a rejected decision?|An error return does not prove the function avoided mutation. Check that rejected input left the protected state unchanged.
7|What is the key difference between while and do-while?|while checks before the body and may run zero times. do-while checks after the body and runs at least once.
7|What are the three parts of a traditional for loop?|Initialization runs once, the condition is checked before each iteration, and the update runs after each completed body, including a continue path.
7|What does the colon mean in for (int x : values)?|It separates the element declaration from the range. The loop gives x a value from each element in values in turn.
7|Why can for (auto x : values) fail to change the collection?|x is a separate value for each iteration. Changing x changes the copy. Use an appropriate reference when mutation is intended.
7|What does break leave when loops are nested?|It leaves only the innermost enclosing loop or switch. It does not automatically leave every outer loop or return from the function.
7|How does continue behave in a traditional for loop?|It skips the remaining body and proceeds to the update expression, then the next condition check.
7|Why can continue cause a while loop to repeat forever?|It may skip the input read or state update that would make progress. Ensure every continuing path advances the loop.
7|What is a sentinel value?|It is an input value reserved to mean stop. Test it before treating it as ordinary data when the requirement excludes it from calculations.
7|What is a loop invariant in plain language?|It is a rule about the changing state that stays true at a chosen point each iteration. It explains what the processed prefix means.
7|What should be true about a running sum and accepted count?|They must describe the same accepted items. Skipped or sentinel values must not increase either one under that contract.
7|Why check count before calculating an average?|An empty accepted set has count zero. Dividing by zero is invalid; the application needs an explicit no-data result.
7|What does a trace table reveal that final output can hide?|It shows input, decisions, counts, and totals at each step. A later value can accidentally mask an earlier wrong update.
8|How does a function declaration differ from its definition?|A declaration introduces the callable interface. A definition supplies the body. Calls need a visible suitable declaration and the program needs the required definition.
8|What is a parameter compared with an argument?|A parameter is the function's named input in its declaration. An argument is the expression a caller supplies for a particular call.
8|What happens to a caller's int passed by value?|The function receives its own int value. Changing that parameter does not change the caller's int.
8|What does int& in a parameter mean?|The parameter is a reference: another name for an existing int. Assignment through it changes the referred-to caller object.
8|Why often return a calculation's result?|It makes data flow visible at the call site and avoids unnecessary mutation. Use reference outputs only when their added behavior is justified.
8|Does printing inside a helper count as returning its result?|No. Output is a side effect; return sends a value to the caller. A reusable calculation should normally let the caller choose how to present it.
8|Can functions be overloaded only by changing the return type?|No. Calls could not choose between them based only on what value comes back. Valid overloads need suitable differences in their parameter lists.
8|When is a default argument used?|It supplies an omitted argument at a call where that default is visible. Passing an explicit argument uses the caller's value instead.
8|Why write a function contract?|It states allowed inputs, results, changes to state, and failure behavior. Tests can then target promises rather than guess from the function name.
8|What does return do to later statements in the same function call?|It ends that call's execution. Later statements on that path do not run; control returns to the caller.
8|Why can a magic error value weaken a calculation API?|A caller may treat it as an ordinary result. Make failure distinct or state a contract that reliably separates error and valid values.
8|How does a small pure calculation help maintenance?|Given the same inputs it gives the same result without hidden changes. It can be tested separately from terminal input, files, and user interfaces.
9|How do scope and lifetime differ?|Scope is where a name can be used. Lifetime is when an object exists. A local static name has small scope while its object persists across calls.
9|What happens when an inner variable shadows an outer one?|The inner name selects the inner object in that scope. The outer object still exists, but an unqualified use of the name does not select it there.
9|When does an ordinary local object's lifetime normally end?|At the end of the block or when control leaves it. Cleanup occurs for constructed class objects as required by the exit path.
9|How does a function-local static differ from an ordinary local?|It is initialized when control first reaches its declaration and keeps state between calls. The name is still local to the function's scope.
9|Why can persistent counters make tests order-dependent?|One test changes hidden state that the next test sees. Passing caller-owned state lets each test start with a known independent value.
9|Does returning a pointer extend a local object's lifetime?|No. If the local object dies when the function returns, the returned pointer dangles. The address value does not keep the object alive.
9|Why avoid reading an object after its lifetime has ended?|The object's valid lifetime no longer covers that use. Memory may look unchanged, but its old bytes do not establish a valid object access.
9|Why can broad global mutable state make debugging harder?|Many functions can change it, so a failure depends on hidden earlier actions. Narrow ownership and explicit parameters reduce those paths.
9|What should a lifetime diagram record?|Each object's creation, uses, destruction, and any borrowing handles. A borrow must end before the owner's relevant lifetime ends or storage is invalidated.
9|What does static storage duration say, and what does it not say?|It describes how long storage persists. It does not make an object immutable or make shared mutations safe.
9|Why should a local static initialization failure be considered?|If initialization throws, the object was not successfully initialized; a later call can attempt initialization again. Do not claim success from merely entering the function.
9|How can a caller-owned counter improve an API?|The caller supplies and can inspect the state. Tests can create separate counters, and the function no longer hides a process-wide sequence.
10|Which indices are valid in an array of four elements?|0, 1, 2, and 3. Four is the count and the one-past boundary, not the index of a fifth accessible element.
10|What happens to omitted int elements in int a[4]{1,2};?|They are initialized to zero. The resulting elements are 1, 2, 0, and 0.
10|Why prefer i < count over i <= count for traversal?|The strict comparison stops before the one-past boundary. <= permits an access at index count, which is outside the array.
10|Does raw array indexing check the bound for you?|No. The program must keep the index in range. Out-of-bounds access is undefined behavior even when a test seems to print a value.
10|What does an array's decay usually produce?|In many expression contexts it converts to a pointer to the first element. That pointer alone does not carry the array's element count.
10|Why does sizeof(a) inside a function taking int a[] not measure the caller's array?|That parameter is adjusted to a pointer type. sizeof measures the pointer there, not all the caller's elements.
10|Why pass a length with a borrowed raw array?|The callee needs a valid range to traverse. The caller must ensure the pointer and length describe live accessible elements.
10|What does std::span add to a borrowed array interface?|It carries a view of a contiguous range with its size. It does not own the elements or extend their lifetime.
10|How do a two-dimensional array's row and column bounds differ?|Each index belongs to its own extent. Check the row against the row count and the column against the column count.
10|Why can a range-based loop reduce indexing mistakes?|It visits the actual elements of the range without hand-written index bounds. It still needs the correct value or reference declaration.
10|Why not return a view of a local array?|The local elements die at return. The returned view would refer to expired elements; return an owning value or borrow longer-lived storage.
10|What tests help a fixed-shape calculation stay correct?|Test each position, mixed signs, zeros, and a changed shape during maintenance. Verify both dimensions rather than assuming a square grid.
11|What does std::string own?|It owns its character sequence and manages its storage. A string object can grow; a borrowed character pointer is not the same ownership boundary.
11|How do += and assignment differ for a string?|+= appends to existing text. Assignment replaces the existing sequence with the supplied text.
11|What does string::size() count?|It counts char elements. For UTF-8 text, that is not necessarily the number of human-perceived characters.
11|What does find return when the requested text is absent?|std::string::npos. Check that absence marker before treating the result as a valid position.
11|Why can adding one to npos create a wrong substring calculation?|npos is an absence marker, not a found index. Arithmetic on it does not turn a failed search into a valid delimiter location.
11|How does substr(position, count) interpret count?|It is the requested number of characters, not an ending index. The result is limited by the remaining sequence; an out-of-range starting position throws.
11|How does operator>> into a string differ from getline?|Formatted extraction reads a whitespace-delimited word. getline reads up to its delimiter, allowing spaces inside the line.
11|Why can getline read an empty line just after reading a number?|The formatted read can leave the newline in the stream. getline then consumes that newline immediately. Handle the transition deliberately.
11|What two results from from_chars must a strict integer parser check?|Check the error code and the returned pointer. Success without reaching the field's end can mean only a numeric prefix was parsed.
11|Does from_chars skip leading spaces in this integer use?|No. It follows its specified numeric format rather than the stream's whitespace rules. Decide whether trimming belongs in your input contract.
11|Why parse into a temporary before updating saved state?|A rejected field can then leave the prior value unchanged. Commit only after representation and domain checks succeed.
11|How can a string edit invalidate a borrowed character pointer?|An edit may reallocate storage. Reacquire the pointer after the edit and do not assume old addresses still refer to live characters.
12|When is std::array a good collection choice?|When the number of elements is part of the fixed requirement. It owns a fixed extent and carries that size in its type.
12|When is std::vector a better choice than std::array?|When the number of elements changes at runtime. It owns a sequence whose logical size can grow or shrink.
12|How do vector size and capacity differ?|Size counts live elements. Capacity describes available storage before a growth reallocation is needed. Reserved storage is not a set of extra elements.
12|What does reserve(10) guarantee about an empty vector's size?|The size remains zero. Capacity is at least ten if the call succeeds. Indexing element zero is still invalid until an element exists.
12|What does resize(3) do to an empty vector<int>?|It creates three elements, initialized to zero in this case. Unlike reserve, it changes the logical size.
12|Why can push_back invalidate a reference to an element?|If growth reallocates storage, existing element references and pointers are invalidated. Do not keep using a borrower after that boundary.
12|What does pop_back require?|The vector must not be empty. It destroys the last element and decreases size; it does not return that element's value.
12|How does at() differ from operator[] for these containers?|at() checks the index and throws on an out-of-range index. [] requires the caller to meet its bounds contract.
12|Why should tests avoid demanding capacity == requested reserve size?|reserve guarantees sufficient capacity, not that every implementation chooses exactly that capacity. Test the guarantee your design relies on.
12|What lifetime does a vector own for its elements?|Their lifetime belongs to the vector's construction, growth, removal, and destruction operations. A reference to an erased element does not survive its removal.
12|How does copying a vector differ from borrowing it?|A copy owns separate elements. A const reference observes the existing vector without taking ownership and without permitting mutation through that reference.
12|What should a bounded append function guarantee on rejection?|It should preserve all previous elements and the size. Returning false after appending a forbidden value violates that unchanged-state contract.
13|What does int& alias = value; create?|It creates a reference bound to value. The two names refer to the same int object; it does not create a second independent int.
13|Can assignment reseat an existing reference?|No. alias = other assigns to the object alias already refers to. It does not make alias refer to other instead.
13|Why must an ordinary reference be initialized?|It needs a target when it is created. A declaration such as int& r; cannot leave it waiting to be bound later.
13|What does const std::vector<int>& promise at this access path?|The function borrows the vector and cannot mutate it through that reference. Other allowed access paths may still exist; const is not a global freeze.
13|Why use a value parameter for a small input like int delta?|It is cheap to copy and makes an independent input. A reference is useful only when borrowing or caller-state mutation is part of the contract.
13|What does auto& change in a range-based loop?|It binds the loop variable to each actual element. Changes through it affect the collection; auto alone would create a separate value.
13|Why can a returned reference be unsafe even if the type is correct?|Its target may already be dead or become invalidated. Type checking does not by itself prove that the caller's later use occurs within the target's lifetime.
13|What is aliasing in a function call?|Two parameters or names can refer to the same underlying object. A design must account for that when writes affect later reads.
13|Why validate a whole batch before modifying its first element?|Otherwise a late invalid element can leave earlier elements changed. Validate first or use a candidate copy when rejection must preserve the original collection.
13|Does a const reference always avoid all lifetime concerns?|No. It still borrows an object. The binding context determines any temporary lifetime extension; returning a reference to expired data remains unsafe.
13|How can the caller understand whether a helper mutates input?|A non-const reference signals possible mutation, but a clear name and documented contract explain when changes happen and what failure preserves.
13|What must stay true while a function borrows a collection?|The collection and referenced elements must remain alive, and operations must not invalidate borrowers that are still used. The borrow does not own them.
14|How do &value and *pointer differ?|&value obtains the object's address. *pointer refers to the target object, if that pointer is valid for such access.
14|What does nullptr represent?|It is the null pointer value: no target object. It can express an absent optional selection and must not be dereferenced.
14|Why initialize a pointer to nullptr instead of leaving it uninitialized?|It establishes a known no-target state. It still needs a valid live target before dereferencing.
14|Does pointer != nullptr prove that dereferencing is safe?|No. A nonnull pointer can dangle, refer one past an array, or refer to storage unsuitable for the access. Check the full lifetime and range contract.
14|What happens when you copy a raw pointer?|You copy an address value. Both pointers may refer to the same object; neither copy automatically creates ownership or a new target object.
14|How does ++pointer differ from ++*pointer?|The first advances the pointer within a valid array range. The second increments the pointed-to value. Parentheses and a clear trace help show the intended change.
14|What is a one-past pointer allowed to do?|It can mark a valid array range's end and participate in permitted comparisons or arithmetic. It cannot be dereferenced as an element.
14|What does pointer subtraction measure within one array?|It measures the element-distance between suitable pointers into that array or its one-past position. It is not arbitrary address subtraction across unrelated objects.
14|Why might a find function return a pointer rather than a reference?|A pointer can express no match with nullptr. Its contract must also state that a successful result borrows the caller-owned element.
14|Why not delete a pointer returned to an element in a caller's vector?|The vector owns its storage and elements. The borrowed pointer does not grant permission to release that allocation.
14|What event can invalidate a selected vector-element pointer?|Reallocation, erasing the element, or destroying the vector can invalidate it. Do not keep using the selection after such an event.
14|Why prefer a half-open [begin, end) traversal?|begin denotes the first element and end the excluded boundary. The loop stops before dereferencing end, and an empty range has begin == end.
15|How does automatic storage differ from dynamic allocation?|An ordinary local object's storage follows its block's rules. A dynamic allocation needs an ownership policy that eventually releases it, often through an automatic owner.
15|What does new int{7} produce?|It creates a dynamically allocated int initialized to seven and returns a pointer to it. That raw pointer must be assigned a clear release responsibility.
15|Why must new[] and delete[] be paired?|Array allocation and array deallocation have matching rules. Using a mismatched delete form is undefined behavior, even if the test does not crash.
15|Does leaving the scope of a raw pointer delete its target?|No. Destroying the pointer object does not release the allocation it points to. An owning wrapper can supply that cleanup rule.
15|What is a memory leak?|An allocation remains unreleased after the program loses or fails to use its release responsibility. Reassigning the only raw owner can lose access to the old allocation.
15|What is double deletion?|The same allocation is released more than once. A second release uses storage that has already been freed and has undefined behavior.
15|Why set one deleted raw pointer to nullptr only as a local aid?|It removes that variable's dangling address, but other aliases may still dangle. It does not repair the whole ownership design.
15|What does std::unique_ptr own?|It holds sole ownership of a managed object or array under its deletion policy. Its destruction releases that resource automatically.
15|Why can a unique_ptr be moved but not ordinarily copied?|Copying would create two sole owners of the same resource. Moving transfers ownership and leaves the source without that resource.
15|What does make_unique<int[]>(n) buy you?|It creates an owning array handle with automatic array deletion. The elements are value-initialized here; accesses must still remain within n.
15|What is RAII in plain language?|Resource acquisition is initialization: attach a resource to an object's lifetime. The object's cleanup releases it on normal scope exit and appropriate exception unwinding.
15|When is vector simpler than an owning dynamic array?|When the program also needs a stored size, growth, and collection operations. A unique_ptr array manages ownership but does not itself store the array length.
16|What problem does a struct solve for related fields?|It groups fields into one record so the program can pass, store, and update them together. It does not automatically validate their combination.
16|What does record.weight select?|The dot operator selects the weight member of that record object. A pointer to the record uses -> for member access instead.
16|How do struct and class default access differ?|struct members are public by default; class members are private by default. Both can use explicit public and private access sections.
16|Why name enum values instead of scattering integer status codes?|Names expose valid states and their intent. Raw numeric codes invite mismatches and unclear comparisons.
16|What does enum class add compared with an unscoped enum?|It scopes the enumerator names and does not implicitly convert them to integers. Use names such as Status::ready for clearer type boundaries.
16|Does a public struct prevent a negative weight?|No. A caller can assign it unless another rule or interface stops that assignment. Validate before operations that rely on positive weight.
16|Why can a record's fields each be valid but the record be invalid?|Relationships between fields may fail, such as start exceeding end. Check the combined invariant, not only each field's individual range.
16|What does aggregate initialization of a simple record show?|Brace values initialize the corresponding members in order, subject to aggregate rules. Order matters, so named meaning and tests help prevent swapped fields.
16|Why should an enum-driven decision define all permitted cases?|The behavior should be clear for each legal state. A fallback can report unexpected values rather than silently accept an invalid transition.
16|What is a permitted state transition?|It is a change allowed by the domain rules, such as pending to ready after validation. Not every possible assignment should be an allowed operation.
16|Why test rejected transitions for unchanged state?|A false result should not hide a partly updated record. Compare the fields before and after the rejected action.
16|When is a plain struct sufficient?|When it represents a simple value and callers can reliably handle validation. A class boundary is useful when every mutation must enforce a shared invariant.
17|What is encapsulation in practical terms?|It puts state behind an interface that controls how it changes. Private fields are useful when public operations consistently preserve the object's rules.
17|What is an invariant of a stock-count class?|For example, count always stays between zero and its allowed maximum. Every successful construction and public operation must preserve that rule.
17|Why validate a withdrawal before subtracting it?|An excessive or negative request can make the count invalid. Rejection must happen before changing state when failure promises no change.
17|What does a const member function promise?|It does not modify the object's ordinary non-mutable state through this. It supports read-only access such as querying an available count.
17|What does this refer to in a member function?|It points to the object on which that function was called. Member access uses that object's stored state rather than a shared unrelated copy.
17|Why is returning int& to a private count risky?|It gives callers a path to assign invalid values without the class's checks. Private spelling alone cannot preserve a rule if a public method bypasses it.
17|How does an object differ from its class?|The class defines a type and operations. An object is one instance with its own state and lifetime.
17|Why put terminal input outside a small stock class?|The stock rules can then be reused and tested independently of a console. The adapter can handle input and presentation while the class protects the domain.
17|What should a rejected stock withdrawal return and preserve?|Return its defined failure result and leave the count unchanged. Tests must check both observations.
17|Why is a getter's returned value often safer than a mutable reference?|The value lets the caller inspect state without gaining direct write access. Use a borrowing interface only when its lifetime and mutation promises are needed.
17|Does adding a class always improve a design?|No. A simple calculation may be clearer as a function. Add a class when coordinated state and an invariant justify the boundary.
17|What tests should follow a new inventory rule?|Add allowed and rejected cases at the new boundary, verify unchanged state on failure, and rerun existing behaviors to catch regressions.
18|What does a constructor establish?|It initializes a new object's bases and members and must establish the required valid state before successful construction finishes.
18|What does the colon after a constructor signature introduce?|It starts the member initializer list. Those initializations happen before the constructor body runs.
18|Why can't a constructor-body assignment initialize a reference member?|The reference must already be bound before the body starts. The initializer list supplies the binding; assignment would operate on the referent.
18|What determines member initialization order?|The order of member declarations in the class, not the textual order of the initializer list. Arrange declarations and initializers clearly.
18|What is a delegating constructor?|It asks another constructor of the same class to perform initialization. This shares a valid starting-state path instead of duplicating rules.
18|Why are default member initializers useful?|They supply an explicit normal starting value unless a constructor overrides that member's initialization. They reduce repeated initialization details.
18|If a constructor throws, does that object's destructor run?|The destructor of the not-fully-constructed object does not run. Already constructed bases and members are cleaned up under the language's rules.
18|In what order are members destroyed?|After the owning object's destructor body, members are destroyed in reverse order of their construction. This matters when members borrow from one another.
18|Why should resource-owning members clean themselves up?|They can release resources even if a later initialization or constructor body throws. Raw resource handles need extra careful cleanup paths.
18|How does a file stream demonstrate lifetime-based cleanup?|An owning stream manages its file resource and closes it during destruction. Error reporting for operations still needs an explicit policy.
18|Why avoid exceptions escaping from cleanup during unwinding?|If cleanup throws while another exception is already unwinding, the program can terminate. Destructors should have a reliable nonthrowing cleanup policy.
18|What evidence helps audit construction failure?|Record which members finished construction, which body ran, the throw point, and the cleanup sequence. Only completed subobjects have destructors called.
19|What belongs in a small public header?|Declarations and necessary type definitions that clients need. Keep implementation details out when clients do not need them to compile.
19|Why include a function's header in its implementation file?|It lets the compiler check the definition against the public declaration. A mismatched signature is easier to catch near its source.
19|What is a translation unit?|A source file after preprocessing has brought in its included material. Each translation unit is compiled separately.
19|What does an include guard protect against?|Repeated processing of a header within one translation unit. It does not solve every cross-translation-unit definition problem.
19|Why can defining a non-inline function in a widely included header break linking?|Multiple translation units can supply competing external definitions. Put one suitable definition in a source file or use an appropriate inline design.
19|What does #pragma once aim to do?|It asks a supporting compiler to process a header only once per translation unit. It is widely supported but is not a standard C++ directive.
19|Why can declaration-only code compile but fail to link?|The caller knows the interface, so translation succeeds. The linker still needs the matching definition in linked objects or libraries.
19|Which files need rebuilding after a shared header changes?|All translation units whose compilation depends on that header. A dependency-aware build system tracks that relationship.
19|Why can linking a stale object create a misleading success?|The object may contain an older interface or implementation. The link command can succeed without translating the latest source.
19|How should a two-file command identify its inputs?|Name all required sources for a combined build, or compile each source to an object and link all required objects. Include paths do not add missing definitions.
19|Why use a namespace for a reusable calculation?|It groups related names and reduces accidental name collisions. It does not replace an accurate declaration or fix missing object files.
19|What makes a useful build reproduction record?|Exact files, compiler and mode, include and link options, working directory, statuses, and a clean rebuild. Preserve enough detail for another developer to repeat it.
20|How do requirements become acceptance tests?|Turn each rule into observable inputs, outputs, and state changes. Include rejection behavior and recovery, not only successful demonstrations.
20|Why separate command parsing from inventory mutation?|Parsing decides what a command means; the domain decides whether it is allowed. This keeps input-format changes from duplicating stock rules.
20|Why reject trailing text after an otherwise valid command?|A strict command format requires the entire input to match. Accepting only a prefix can silently ignore an unintended or malformed instruction.
20|What is a transactional batch update?|It either commits every accepted change or leaves the original state unchanged. A late error must not leave an early partial update behind.
20|Why can a candidate copy simplify a transaction?|Apply changes to the candidate, validate the result, then commit. The original remains intact until every required check succeeds.
20|What should recovery after a bad command prove?|The error is reported, protected state is unchanged, and the next valid command can still succeed. Rejection alone does not demonstrate recovery.
20|Why distinguish standard output from standard error in a test?|The program may promise different channels for normal results and diagnostics. Correct text on the wrong channel still violates that interface.
20|Why test exit status along with output?|Scripts use the status to decide whether work succeeded. Printed success paired with a failure status, or the reverse, can mislead automation.
20|What is a regression test?|It checks behavior that already worked so later changes do not accidentally break it. Keep it while improving internal structure.
20|How does refactoring differ from adding a feature?|Refactoring changes internal organization while preserving intended observable behavior. A feature changes the contract and needs its own acceptance cases.
20|What makes a complete multi-file application maintainable?|Clear responsibilities, authoritative validation, explicit ownership, reproducible builds, and tests for state and failure boundaries support safe changes.
20|Why keep a contract ledger for the capstone?|It links each rule to its implementation and a test witness. Gaps reveal requirements that have been described but not demonstrated.
21|How do you distinguish a compile error from a link error?|A compile error occurs while translating a source unit. A link error occurs while combining objects or resolving definitions. Diagnose the earliest failed boundary.
21|Why start with the first useful diagnostic?|Later messages can be consequences of the first defect. Fix the earliest explained cause, rebuild, and inspect what remains.
21|What is a minimal failing example useful for?|It removes unrelated code while preserving the defect. A smaller reproduction makes the mistaken assumption easier to inspect and test.
21|What evidence closes a debugging investigation?|A reproducing test fails before the fix and passes afterward, related regression tests pass, and the changed assumption is explained.
22|Why can't prechecking each delta independently guarantee a valid batch?|Multiple deltas can interact through the same record. Validate the sequence or combined effect under the actual transaction rule.
22|Why use an original-state snapshot in a rejection test?|It gives a concrete comparison after failure. A false return alone does not show that every original element was preserved.
22|When is validate-then-mutate better than copying?|When validation proves all later changes are safe and nonfailing under the contract. A candidate copy is easier when interactions or failures complicate that proof.
22|What does an atomic commit mean in this single-threaded lesson?|It is all-or-nothing application behavior. It does not claim CPU atomic instructions, thread safety, or a database transaction.
23|Which destructor is absent after an owner's constructor body throws?|The not-fully-constructed owner's destructor. Already constructed member objects are still destroyed in reverse construction order.
23|What cleanup runs if constructing the second member fails?|Only subobjects that completed construction are destroyed. The failing member and incomplete owner do not have their destructors called.
23|Why does a construction log need both start and finish meaning?|A message before a possible throw does not prove construction completed. Define what each logged event actually witnesses.
23|Why prefer lifetime-managed resources in a throwing constructor?|Completed owning members clean themselves up during unwinding. Manually held resources are easier to leak before the owner becomes fully constructed.
24|What distinguishes an acceptance worksheet from a list of intentions?|Each requirement names a test, an observed result, and evidence. A check mark without a witness does not prove the feature works.
24|Why should the capstone include an empty-input case?|It tests startup and termination without normal commands. The program needs a defined result rather than assuming every session contains useful input.
24|Why test a failed command followed by a successful one?|The sequence checks recovery and preserved state. Separate runs can miss failure state that corrupts later commands.
24|What should a final acceptance review say about missing checks?|Identify the missing evidence explicitly. Do not report complete acceptance merely because the available happy-path demonstrations passed.
