1. The Linux Command Line

A colleague sends an administrator a command that “worked yesterday.” On another machine, it copies the wrong files. The utility is not broken. 4. 2.1 Understanding the Shell

A shell is a command interpreter. It reads text, recognizes syntax, performs expansions and redirections, and launches programs or built-in operations. A terminal is the interface carrying your keystrokes and displaying output. The terminal and shell are related but are not the same program.

When you enter printf '%s\n' hello, the shell identifies a command and its arguments. It may use a built-in implementation rather than launch a separate executable. type printf shows how the current shell resolves that name. command -v printf reports a usable command location or identity, but the interpretation remains shell-specific.

This matters when debugging aliases and functions. A command name can be shadowed by a personal alias, function, or earlier directory in PATH. Inspect with type -a name before blaming the system binary. Scripts should not depend on a user’s interactive aliases. (R05)

6. 2.2 Bash Fundamentals

Bash reads commands as a language, not as a collection of words separated blindly by spaces. Quotes group text and control expansion. Single quotes preserve literal characters; double quotes preserve grouping while allowing parameter and command substitution. An unquoted space usually separates words.

The assignment has no spaces around =. In name = value, Bash would attempt to run a command named name. The dollar sign requests the variable’s value; it is not part of the variable’s name.

Use Tab completion to reduce typing errors and Ctrl+C to interrupt a foreground command when appropriate. Ctrl+D signals end-of-input; at an idle shell it may exit the session. Neither key sequence is a universal rollback. A command may already have made changes before being interrupted.

9. 2.3 Commands, Arguments, and Options

An argument is a value passed to a command. An option changes how that command behaves. In ls -l /etc, -l requests a long listing and /etc is the directory operand. Programs define their own option syntax; not every command accepts the same flags.

Many GNU utilities accept -- to end option processing. This is useful when a filename begins with a hyphen:

Without the separator, a program may interpret the filename as an option. A safer general habit is to use explicit paths such as ./-report and consult the command’s help. Understand options before combining them. The difference between a listing and a recursive deletion is not a minor detail just because both accept flags.

12. 2.4 Navigating the Filesystem

pwd prints the current directory. cd changes it. A leading slash makes a path absolute; otherwise the path is interpreted relative to the current directory. . means the current directory and .. its parent.

cd - returns to the previous directory tracked by the shell. It is convenient interactively, but a script should usually establish an explicit working directory and stop if that step fails. Otherwise later relative paths may target an unintended location.

Symbolic links add another distinction. Bash can track a logical path containing a symlink, while the physical directory lies elsewhere. pwd -P resolves the physical location. Before a sensitive operation, verify both the directory and the object being changed rather than trusting the prompt’s shortened path.

15. 2.5 Working with Files and Directories

mkdir creates directories, cp copies, mv moves or renames, and rm removes directory entries. touch creates an empty file when absent or updates timestamps when present. It is not a universal file-content editor.

The -p option tolerates existing directories and creates missing parents. It does not guarantee their ownership or permissions. Copying content also does not necessarily preserve every kind of metadata. Later chapters distinguish ordinary copies, archive-preserving copies, and verified backups.

Treat removal as a state change with no automatic undo. Start with ls or find to display the exact selection. Avoid habitual rm -rf use. A safe lab cleanup can remove one known file with rm -- path; a production cleanup needs a retention rule, scope, and recovery plan.

18. 2.6 Viewing File Contents

Use cat for small files, less for interactive paging, head for the beginning, and tail for the end. wc -l counts newline characters, which usually correspond to lines but may differ for a final unterminated line.

Inside less, /word searches, n moves to the next match, and q exits. Avoid printing binary files directly into a terminal; they may contain control characters. file path identifies a likely file type, and od can display bytes deliberately.

For a growing log, tail -F follows a filename across common rotation behavior, while tail -f primarily follows the opened file. Neither replaces a log retention policy. Seeing the newest ten lines is not enough to reconstruct a failure that began hours earlier.

21. 2.7 Searching with find and locate

find walks a directory tree and evaluates conditions against the entries it encounters. locate, when installed, searches a database of paths and can be faster, but its results depend on database freshness and visibility rules.

Quote *.txt so that find, not the shell, interprets the pattern. Without quotes, the shell may replace it with names in your current directory before find starts. This can change the command or produce an error.

Select before acting. For batch operations on filenames, find ... -exec command {} + avoids splitting names on spaces. A newline-delimited pipeline is not safe for arbitrary filenames containing newlines. -print0 with a NUL-aware consumer is the alternative. Do not start with -delete; first inspect exactly the same selection using -print.

24. 2.8 Text Searching with grep

grep selects lines matching a pattern. -n includes line numbers, -i ignores case, -v selects nonmatching lines, and -F treats the pattern as fixed text rather than a regular expression. Use the simplest pattern language that solves the task.

The illustrative result is 2:ERROR disk full. The 2 is the source line number, not an error code. To inspect the exit status, run printf '%s\n' "$?" immediately after grep.

A no-match result is not the same as a read failure. In automation, distinguish status one from an actual error. Searching recursively through / is rarely a sensible first diagnostic: it crosses virtual filesystems, permissions, and possibly remote mounts. Choose the relevant files or directory first.

27. 2.9 Wildcards and Globbing

Globbing is the shell’s expansion of filename patterns. * matches a sequence of characters within a path component, ? matches one character, and bracket expressions match selected characters. In ordinary Bash settings, a leading dot in a filename requires explicit matching.

Here the home-directory expansion is quoted but the wildcard remains active. The shell produces one argument for each matching path. If there is no match, Bash normally leaves the pattern unchanged; options such as nullglob and failglob alter that behavior.

A wildcard is not a regular expression. *.log is useful as a filename glob; the regular expression .*\.log$ expresses a related text pattern through different rules. Confusing them produces both missed matches and overly broad selections.

30. 2.10 Standard Input, Output, and Error

A process ordinarily starts with three standard file descriptors: 0 for input, 1 for output, and 2 for error messages. A file descriptor is a process-local handle, not necessarily a disk file. It may refer to a terminal, pipe, socket, or device.

Commands generally place useful data on standard output and diagnostics on standard error. That separation lets a pipeline process results without treating a warning as another record. A program that prints everything to one stream is harder to automate reliably.

The successful listing and diagnostic are captured separately. The existence of listing.txt does not prove the whole command succeeded; redirection may create it before the command runs. Check the exit status and inspect both outputs when the operation matters.

33. 2.11 Pipes and Redirection

A pipe connects one command’s standard output to another command’s standard input. > creates or truncates a destination, >> appends, and < reads input from a file. Redirections are processed in order.

2>&1 makes standard error refer to the current destination of standard output. Therefore >file 2>&1 and 2>&1 >file are not equivalent. In the second form, standard error retains the earlier destination.

Do not redirect a transformation back into its own input file: sort data > data can truncate the file before sort reads it. Write a separate temporary file, validate it, and replace deliberately. Chapter 16 develops that pattern. A pipe also does not imply success of every stage; Bash’s default pipeline status comes from the last command.

36. 2.12 Command History

Interactive Bash can record commands for recall. history lists entries, and Ctrl+R searches backward. History is a convenience, not a trustworthy audit trail: settings vary, sessions can overlap, and users can alter their own history.

Never enter secrets as ordinary command arguments merely because you plan to erase history later. The values may also appear in process listings, terminal capture, logs, or monitoring. Use a program’s supported secret-input mechanism.

Before rerunning a command, read it in full. A command appropriate on web1 yesterday may be harmful on a different host today. History remembers syntax, not preconditions. When you turn a useful command into an operational procedure, add the host, scope, validation, and rollback that history cannot supply.

37. 2.12 Command History · example 1

Interactive Bash can record commands for recall. history lists entries, and Ctrl+R searches backward. History is a convenience, not a trustworthy audit trail: settings vary, sessions can overlap, and users can alter their own history.

Never enter secrets as ordinary command arguments merely because you plan to erase history later. The values may also appear in process listings, terminal capture, logs, or monitoring. Use a program’s supported secret-input mechanism.

Before rerunning a command, read it in full. A command appropriate on web1 yesterday may be harmful on a different host today. History remembers syntax, not preconditions. When you turn a useful command into an operational procedure, add the host, scope, validation, and rollback that history cannot supply.

38. 2.13 Environment Variables

A shell variable stores a value in the current shell. An environment variable is exported so child processes can inherit it. Children receive a copy of the environment; changing it in a child does not rewrite the parent’s variables.

PATH lists directories searched for executable commands. Placing an untrusted writable directory early in it can cause the wrong program to run. Administrative scripts should establish a known search path or use justified absolute paths.

Environment variables are not automatically secret. Depending on permissions and the environment, they may be inspectable through process interfaces or captured by diagnostics. Avoid dumping env into support tickets. Display only the variable needed for the question and redact credentials at the source.

41. 2.14 Command Substitution

$(command) runs a command and inserts its standard output into the surrounding command. Bash removes trailing newline characters from that output. Double quotes keep the resulting text grouped as one argument.

This is useful for short values, but not for transporting arbitrary binary data or large files. Shell variables cannot contain NUL bytes. Unquoted substitution can also trigger word splitting and filename expansion.

Capture errors explicitly when the result is essential. A variable being nonempty does not prove the producer succeeded. For example, a command might print partial output before failing. A robust script checks the assignment’s status and validates the value’s shape before using it as a filename or configuration value.

44. 2.15 Shell Expansion

Bash performs several transformations before execution, including brace expansion, parameter expansion, arithmetic expansion, command substitution, word splitting, pathname expansion, and quote removal. You do not need to memorize every edge case immediately, but you must know that a program often receives different text from what you typed.

The first command produces three arguments through brace expansion. The second calculates an integer expression. Braces in this context are not the same as ${count}, which identifies a parameter name.

A practical debugging method is to replace the intended operation with printf '<%s>\n' and inspect the resulting arguments. This reveals grouping and expansion without performing the original action. It is especially useful before using wildcards in copy or removal operations.

47. 2.16 Essential Administrative Commands

Build a small inspection vocabulary before learning large command collections. whoami and id identify credentials. hostname identifies the host. date supplies time context. uname reports kernel information. uptime reports uptime and load averages. df reports filesystem capacity. ps reports processes. ip reports networking. man explains installed interfaces.

Use manual sections deliberately: man 5 passwd describes the file format, while man 1 passwd describes the password-changing program. man -k keyword searches manual descriptions when the command name is unknown.

Interactive editing is also unavoidable. Use sudoedit /path/to/config for privileged text changes when authorized. In nano, save with Ctrl+O and exit with Ctrl+X; in vi, press Esc, use :wq to save and quit, or :q! to abandon edits. Learn one editor well enough to recover a server without a graphical desktop.
