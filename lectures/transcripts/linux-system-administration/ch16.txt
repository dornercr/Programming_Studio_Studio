4. 16.1 Writing Your First Script

Create a text file beginning with #!/usr/bin/env bash, followed by commands. Run it with bash script.sh during development; executable permission plus the interpreter line permits ./script.sh. A .sh suffix is a naming convention, not what makes the file executable.

Start with a harmless program that prints a message and the hostname. Run bash -n script.sh to check shell syntax before execution. This does not validate external commands, permissions, or runtime logic. For privileged deployment, use an approved interpreter path and trusted PATH rather than depending on arbitrary environment contents.

6. 16.2 Variables

Assign with name=value, without spaces around the equals sign. Read a value as "$name" or "${name}". Quoting prevents a value containing spaces or wildcard characters from turning into several arguments or filename matches.

Use printf with a fixed format string. Writing printf "$user_input" treats percent sequences as formatting instructions. A variable is data until you deliberately make a tool interpret it; avoid eval for routine administrative parsing. (R05)

12. 16.4 Exit Codes

A command returns zero for its defined success and nonzero for other outcomes. Capture a status immediately if it is needed. grep is a classic distinction: one means no match, while a larger status indicates an error. Treating all nonzero statuses as the same can turn a missing file into an empty report.

The else branch receives the failed command’s status here. By contrast, if ! command negates the condition, so careless status capture after ! can record the negated result rather than the original failure.

15. 16.5 Conditionals

Bash’s [[ ... ]] tests strings and file properties without the ordinary word-splitting behavior of unquoted command arguments. Arithmetic conditions use (( ... )). Keep the form aligned with the data rather than comparing numbers lexically.

An existence check is not a permanent guarantee. Another process can replace a file between checking it and using it. For teaching scripts, explicitly require a trusted directory and single writer. Security-sensitive privileged operations need stronger ownership, descriptor, locking, and race-resistance designs than a few shell tests can promise.

17. 16.6 Loops

Use for to iterate over known arguments or arrays. Use while IFS= read -r line to read lines without trimming whitespace or interpreting backslashes. Do not use for file in $(ls); whitespace and newline-containing filenames make it unreliable.

For arbitrary filenames from find, use NUL-delimited output and a compatible reader. For a small explicitly controlled fixture, ordinary names may suffice, but document that assumption. Bound loops that wait for a service: give them a maximum number of attempts and a timeout for each external call.

19. 16.7 Functions

Functions name a coherent operation and reduce repetition. A small logging function can write a fixed timestamped format to standard error. Use local variables inside functions to avoid unintentionally changing the caller’s state.

A function should make its output contract clear. If it returns data through stdout, keep diagnostic messages on stderr so the caller does not parse a warning as a filename. Do not hide privileged mutations in a function whose name sounds observational, such as check_storage, unless its behavior is explicit.

24. 16.9 Input and Output

Standard input carries incoming data, stdout carries the main result, and stderr carries diagnostics. Redirect them deliberately. A report saved with command >report 2>errors separates results from problems, while 2>&1 combines streams at the point the redirection is evaluated.

Write replacement files into a temporary file in the destination directory, validate them, then rename into place. This avoids exposing a partially written file to readers on the same filesystem. It does not make a multi-file deployment transactional or remove concurrency concerns. Preserve intended ownership, permissions, and security context separately.

26. 16.10 grep, sed, and awk

Use grep to select matching lines, sed for controlled stream transformations, and awk for record-and-field calculations. For a known whitespace-delimited fixture, awk '{total += $2} END {print total}' data.txt sums the second field.

These are not universal parsers. JSON, YAML, CSV with quoted delimiters, and nested configuration formats need suitable parsers or carefully specified constraints. A global sed -i replacement can modify comments and unrelated keys; prefer a template or format-aware tool for configuration management.

28. 16.11 Regular Expressions

A regular expression describes a text pattern. ^ anchors the start, $ anchors the end, and character classes restrict allowed characters. Regex syntax varies between basic, extended, and tool-specific forms; grep -E requests extended expressions.

A filename wildcard is not a regular expression. Shell *.log matches filenames according to glob rules, while a regex such as .*\.log$ has different meaning. Prefer fixed-string grep -F when the requirement is a literal token. Fewer interpreters mean fewer accidental surprises.

30. 16.12 Error Handling

Handle expected alternatives explicitly and unexpected failures visibly. Validate dependencies before starting a change, retain the old output until new output is complete, and remove only temporary artifacts you created. A trap can clean up a known temporary file when the script exits.

Cleanup must not erase evidence or replace the original failure with success. Avoid broad traps such as rm -rf "$workdir" when workdir can be empty or externally supplied. The worked script removes only the exact temporary file returned by mktemp in a trusted directory.

32. 16.13 set -euo pipefail

set -e requests exit for certain unhandled failures, -u rejects many unset-variable expansions, and pipefail makes a pipeline fail when a component fails rather than considering only the last command. These settings catch mistakes, but they are not an exception system.

-e has important exceptions in tests, conditional lists, pipelines, and functions called in conditional contexts. Command substitutions also have nuanced inheritance behavior. Arithmetic expressions such as ((count++)) can return nonzero when their expression evaluates to zero. Use explicit checks for critical operations and test failure paths instead of assuming “strict mode” proves correctness. (R36)

34. 16.14 Logging

A useful script log identifies the operation, target, outcome, and time without exposing secrets. Write diagnostic lines to stderr and use a stable format. If stdout is intended as machine-readable data, keep it free of decorative progress messages.

Do not enable set -x around secrets: tracing can reveal expanded arguments and assignments. Debug a sanitized fixture first. An administrator should be able to tell the difference between “nothing changed,” “change completed,” and “operation failed before any change.”

38. 16.16 Writing Safe and Idempotent Scripts

An idempotent operation reaches the same intended state when repeated. It does not append another duplicate line or restart a healthy service without need. Compare the desired file with the existing file and replace only when content differs.

Idempotence is not the same as safety or atomicity. Repeatedly deleting the wrong directory can be idempotent and disastrous. A safe script validates its target, limits privileges, reports errors, and respects concurrency assumptions. Tests should include unchanged input, invalid input, paths containing spaces, and an existing output that must survive failure.
