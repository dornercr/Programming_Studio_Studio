Appendix D — Working glossary

1. Appendix D — Working glossary

Access control list (ACL). Additional file access entries for named users and groups, evaluated with the ACL mask where applicable. See Chapter 5.

Atomic replacement. A change that exposes an old or new directory entry rather than a partially written replacement at that entry. It does not make multiple files or external systems one transaction. See Chapter 16.

Authentication. Establishing an identity. Authorization decides what that identity may do. Successful authentication does not imply permission for every operation. See Chapters 4 and 12.

Availability. The service’s ability to satisfy a stated request or time-based success condition. Define the measurement before reporting a percentage. See Chapter 29.

Backup. A retained recovery copy with the data, integrity, access, and independence needed for its declared recovery purpose. A second live replica is not automatically such a copy. See Chapter 21.

Block device. A device interface used for block-oriented storage. A filesystem may sit on a partition, logical volume, or another layered block device. See Chapter 9.

Canary. A deliberately limited initial deployment used to observe a change before wider rollout. Its result is meaningful only when the test conditions represent the intended rollout. See Chapters 27 and 29.

Capability. A defined portion of traditional privileged Linux operations. A capability can still be extremely powerful. See Chapter 17.

Cgroup. A control group that organizes processes for resource accounting and control. Namespace isolation and resource limits are related but distinct mechanisms. See Chapters 7 and 26.

CIDR. Prefix notation describing the network portion of an IP address, such as /24 for an IPv4 prefix with 24 network bits. See Chapter 11.

Configuration drift. A difference between intended and observed configuration. Not every difference is unauthorized, but every material difference needs classification. See Chapters 27 and 29.

Daemon. A service process intended to operate without an interactive human session. Its process lifetime is managed separately from a user’s terminal. See Chapters 8 and 19.

Desired state. A declared outcome that configuration management attempts to establish and maintain. A dangerous desired state can be perfectly idempotent. See Chapter 27.

DNS resolver. A component that obtains name-resolution answers. Application name resolution can also include sources outside DNS. See Chapter 13.

Exit status. A process result code. Zero conventionally means success, but nonzero values require the tool’s specific interpretation. See Chapters 2 and 16.

Filesystem. The structures and implementation used to organize named files and their metadata on a storage or virtual interface. See Chapters 3 and 9.

Hard link. Another directory entry naming the same inode on the same filesystem. A symbolic link instead contains a path used in later pathname resolution. See Chapter 3.

Idempotency. Repeating an operation produces the same intended state rather than accumulating additional changes. It does not establish safety by itself. See Chapters 16 and 27.

Initramfs. An early userspace image used during boot to prepare access to the real root filesystem and perform related startup work. See Chapter 8.

Inode. A filesystem object recording metadata and references used to locate file data. A filename is held in a directory entry, not as the object’s sole identity. See Chapter 3.

Journal. In the systemd context, the collected structured log store. A filesystem journal is a different mechanism for recording certain filesystem updates. See Chapters 9 and 14.

Least privilege. Granting the access needed for a defined operation without unrelated authority. The requirement, not a generic role label, determines the grant. See Chapter 17.

Load average. Linux’s averaged count of runnable tasks and tasks in certain uninterruptible waits. It is not simply a CPU percentage. See Chapter 7.

Logical volume. An LVM-managed virtual block device allocated from a volume group’s storage. The filesystem above it has separate size and repair rules. See Chapter 10.

Mandatory access control. System-enforced policy that can restrict an operation even when ordinary owner/group permissions permit it. See Chapters 17 and 18.

Mount point. A path where a mounted filesystem becomes visible in a mount namespace. The underlying directory still exists when the mount is absent. See Chapters 3 and 9.

Namespace. A kernel mechanism that separates a class of resource views, such as process IDs or mounts. It is not a complete security guarantee by itself. See Chapter 26.

Out-of-memory event. A condition in which allocation fails or an OOM mechanism selects a process for termination under the relevant memory scope. A cgroup can hit its limit before the host exhausts all memory. See Chapters 7 and 22.

Package repository. A source of package metadata and software artifacts used by a package-management system. Trust, release compatibility, and lifecycle matter as much as reachability. See Chapter 6.

Reverse proxy. A server that accepts client requests and forwards them to an upstream application under a defined routing and trust policy. See Chapter 19.

RPO. Recovery point objective: the tolerated data-loss window expressed as how far back recovery may need to go. RTO is the target elapsed time to restore the defined service. See Chapter 21.

Runbook. A tested operational procedure with preconditions, actions, verification, and recovery. It should be usable by someone other than its author. See Chapters 29 and 33.

SELinux context. A label containing fields such as user, role, type, and level that policy can use to decide access. Ordinary ownership is a separate layer. See Chapter 18.

Service-level objective. A stated target for a defined service indicator over a defined measurement window. It is not meaningful without the indicator and scope. See Chapter 29.

Snapshot. A representation of storage or machine state at a point in time, with consistency and dependency properties determined by the implementation. Independence from the original storage is not automatic. See Chapters 10, 21, and 25.

Socket. An endpoint for communication. A listening socket establishes that a process accepts a class of connections, not that its application answers correctly. See Chapters 11 and 19.

System call. A controlled entry through which a userspace process requests an operation from the kernel. See Chapters 1 and 24.

TLS. Transport Layer Security, a protocol family used to protect communications and establish peer identity under a verification policy. Turning verification off removes an essential part of that policy. See Chapters 19 and 33.

Unit. A systemd-managed object, such as a service, timer, mount, or target. Its active, enabled, and healthy states are not synonyms. See Chapter 8.

Virtual machine. A guest computing environment with a virtual hardware boundary and its own kernel. A container usually shares its host kernel instead. See Chapters 25 and 26.

Zombie process. A terminated process whose exit information remains until its parent or another responsible reaper collects it. Killing it again does not make the missing reap occur. See Chapter 7.

2. Read the operational contract

Keep the source procedure, its preconditions and its verification together. Follow the named primary documentation for the installed version. A command copied without its surrounding assumptions answers a different question.
