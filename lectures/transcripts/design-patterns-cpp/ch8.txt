1. A project can contain smaller projects
Problem and first design

SAY
A work planner starts with three steps: ten minutes, twenty minutes, and five minutes. Adding them is easy. The next requirement says that the first two steps belong to a smaller group, and that this group belongs to the larger project alongside the five-minute step. Later there may be more levels. The total should still be thirty-five. Before choosing a pattern, notice the repeating question: how much time is beneath this item? That question makes sense for both one step and an entire project. The chapter allows zero minutes and empty groups, and rejects totals above ten thousand. Those edge rules are part of the design.

4. One question, two kinds of answer
Problem and first design

SAY
Now we can explain the chapter's choice. Composite gives individual items and containers one useful contract over a tree. Work supplies minutes. Step holds a checked duration and returns it. Group holds children that are themselves Work objects and adds their answers. A child may therefore be another group without changing the parent's loop. The value-based Node demonstration remains a reasonable alternative when one data representation is enough. The Work family becomes useful when distinct kinds of work need their own implementations while callers keep one query. We do not add child-editing operations to every Work merely to make every class look alike.

5. The contract we must preserve
Requirements and mechanism

SAY
A nested work plan. A fixed tree with one shared query lets the same algorithm measure leaves and groups. Bottom-up construction and unique_ptr make lifetime clear.

Support nested groups and individual steps through Work::minutes. Own every child exactly once; reject null children. Allow zero and totals through 10000; reject larger totals.

Every child is non-null and owned once. Every successful child result is in the allowed nonnegative range. A group visits each child once and does not retain a running total between calls. These are the rules that define a correct extension, even if it has the right C++ types. A flat vector is better when there is no nesting. A tagged value tree can avoid virtual functions for a closed set of node kinds, but every added kind then requires editing the variant-handling code.

6. A flat list works until a task contains tasks
Requirements and mechanism

SAY
A work plan contains steps measured in minutes. A step lasts from zero to ten thousand minutes. A group may contain steps and smaller groups. The tool must report the total for either a single step or an entire project. An empty group totals zero. A result above ten thousand minutes is rejected rather than silently accepted. This upper bound is a business rule and also makes integer arithmetic easy to reason about.

For a flat list, start with a vector of integers and a loop that adds them. Nothing about that problem requires a class family. The limitation arrives when groups can contain groups. Keeping one vector for steps and another for groups forces each caller to understand both types and every nesting level. A hard-coded loop for two levels fails as soon as a third group appears. We need one operation whose meaning stays valid at any depth.

7. One operation for a part and a whole
Requirements and mechanism

SAY
Composite is a design for a tree whose individual items and containers support the same useful operation. A tree is a structure with one root and child branches, where following child links never leads back to an ancestor. A leaf has no children. In this example Step is a leaf, Group is a container, and Work is their shared contract. Work::minutes asks for total work time without asking which kind of object receives the request.

Step returns its stored duration. Group asks each child for its minutes and adds the answers. A child group repeats that process. This repeated call on a smaller part of the same problem is recursion. Recursion stops at a Step or an empty Group, so each valid finite tree eventually returns a result. A caller needs only one expression, work.minutes(), whether it measures one step or a project containing many groups.

The contract deliberately does not put add or remove on Work. Adding a child makes sense for a container but not for a leaf. Pretending every leaf can accept a child would create confusing no-op methods or runtime errors. Our groups receive their full child lists during construction and then expose only the query. That is enough for the current requirement and keeps the assembled topology stable.

8. Build ownership from the leaves upward
Requirements and mechanism

SAY
Children is a type alias for a vector of unique_ptr<Work>. The vector owns its pointer objects, and each unique_ptr owns exactly one Work object. The virtual destructor in Work ensures that deleting through the base type destroys a complete Step or Group. When a group is destroyed, its vector destroys its children. Child groups then destroy their own children. The project owns the complete tree through a chain of clearly stated owners.

main first creates two Step objects for ten and twenty minutes. It moves their vector into a Group, then moves that child group into another vector alongside a five-minute Step. Finally it moves that vector into project. std::move permits ownership transfer; it does not copy the work objects. The source vector remains valid after its move, but the program does not depend on its size or contents. Its old children are now owned through the new container.

Group rejects a null child in its constructor. If validation throws, already-constructed member objects are destroyed automatically, including their owned children. No manual delete loop is needed. Since the public API only builds groups from completed children and does not later attach an existing group beneath a descendant, ordinary bottom-up construction yields an acyclic tree. This does not excuse creating a unique_ptr from an already-owned raw pointer; that would violate ownership rules before this API could protect the program.

9. Follow the return values, not just the arrows
Requirements and mechanism

SAY
For the supplied project, the outer Group starts total at zero. Its first child is another Group. That inner group receives ten from its first leaf and twenty from its second, then returns thirty. The outer group adds thirty and next receives five. It returns thirty-five. Each group has its own local total. The locals exist in separate function calls, so the inner subtotal does not overwrite the outer subtotal.

In for (const auto& child : children_), the colon means take each element from children_ in sequence. child is a const reference to a unique_ptr already in the vector. It is not a copy; unique ownership must not be copied. The arrow in child->minutes() follows the pointer to the owned Work object and calls its virtual function. const on minutes says the operation does not change the tree through that interface. Every invocation computes fresh local state instead of storing a running total in a member.

Before adding n, Group checks whether n is greater than 10000 - total. If so, it throws overflow_error. Despite the exception name, the rejected condition here is the project's allowed budget, reached well before the built-in int limit. Testing before addition avoids doing an unsafe addition and only checking after damage. The nonnegative child contract makes the subtraction and comparison meaningful. A future Work implementation that returns negative minutes would break that contract even if its code compiled.

10. Cost, depth, and the limits of uniform operations
Requirements and mechanism

SAY
The compiler checks that Step and Group provide minutes, and that an owning vector cannot be copied accidentally. At execution, virtual dispatch selects the correct child operation at each link. A complete query visits every node once, so its work grows in proportion to the number of nodes. Recursive calls use stack space proportional to tree depth. A million siblings and a million nested groups pose different risks: the latter may exhaust the call stack.

For an untrusted input format, enforce a depth limit while parsing or use an explicit stack for traversal. Our small, internally assembled tree has no parser and no arbitrary-depth guarantee. Caching a group total could make repeated reads cheaper, but would add invalidation concerns if editing later becomes possible. Since this tree is fixed after construction, storing a checked total at construction could also be reasonable when queries dominate. The example recomputes totals so the recursive mechanism stays visible.

Composite fits operations that make sense on both a part and a whole. A total duration qualifies. A command such as set_leaf_duration does not naturally apply to every container. Keep type-specific editing outside the uniform query contract. When maintaining the system, add a new leaf only after defining how it contributes to totals, ownership, and failure behavior. A new class name alone does not make a safe new component.

11. Recursion and virtual dispatch do different jobs
Mechanism in C++

SAY
Two mechanisms cooperate in the chapter, and each answers a different question. Recursion says to ask a child the same minutes question. Virtual dispatch decides which implementation answers for that child object. A Step returns immediately. A Group enters another loop and asks its own children. On a finite acyclic tree, repeated descent eventually reaches a leaf or an empty group. A tree means that following child links cannot lead back to an ancestor. Without that rule, repeated calls might never finish. The ordinary bottom-up construction in this program supports the tree rule, but a future editing API would need to preserve it explicitly.

12. Each recursive call owns its own subtotal
Mechanism in C++

SAY
Do not picture one total variable being passed around the whole tree. Every call to Group::minutes creates its own local total. The outer call pauses while the inner group computes thirty using a different local variable. Once the inner call returns, its local storage ends and the returned integer becomes available to the outer call. The outer call adds that thirty, then asks its second child for five. This explains why setting total to zero at the start of each call is correct. Storing one shared running total in a member could make repeated queries accumulate old work or make concurrent queries interfere.

13. Ownership follows the same tree shape
Mechanism in C++

SAY
Children is a type alias: a shorter name for a vector of unique_ptr values that own Work objects. The vector owns those handles, and each handle is responsible for deleting one child. A child Group repeats the ownership arrangement below itself. Moving a finished vector into Group transfers those owners without copying the work objects. Std::move permits this transfer; it does not prove that the moved-from vector is empty, and this program does not depend on that. Work has a virtual destructor so deletion through the base type reaches the correct Step or Group destructor. The root therefore controls the complete subtree lifetime.

14. Validate the topology and the arithmetic
Mechanism in C++

SAY
The tree contract contains more than correct class names. A null child would make the arrow call invalid, so Group rejects it while taking ownership. If construction throws, completed member objects clean up automatically, including their unique owners. During a query, the duration contract says each child returns a nonnegative value. Group tests whether the next contribution exceeds the remaining budget before addition. The thrown overflow_error describes the project's budget rejection here, not evidence that signed integer overflow already happened. If a future Work implementation returns negative minutes, it can violate this reasoning even though its override compiles. New implementations must honor the same semantic range.

15. Const references make the child loop readable
Mechanism in C++

SAY
Read the child loop from left to right. Const auto ampersand declares a read-only reference to each element already stored in the vector. Auto lets the compiler infer the unique_ptr type, and the reference avoids trying to copy an exclusive owner. The arrow follows that pointer to the Work object and calls minutes. The lab adds steps with the same structural recursion but a different meaning: a zero-minute Step still counts as one leaf. Do not derive leaf count from duration, because zero is a valid duration. Each full traversal visits each node once, and active recursive calls grow with the nesting depth.

19. Accept a completed owned subtree
UML and source walkthrough

SAY
Construction transfers a list of exclusive owners and rejects a missing child. This is the point where a new Group takes responsibility for its subtree. Validating once prevents every later query from having to handle null children.

The comment identifies an ownership transfer. Receive the completed vector by value. Move its owners into the member vector. Borrow each pointer entry while validating it. Test whether an entry contains no object. Begin throwing a constructor argument error. Name the invalid child argument. Close the missing-child branch. Close the validation loop. Finish construction with a valid list.

All accepted entries own real Work objects and remain inside the group. Manually manufacturing duplicate owners can still violate unique_ptr rules.

20. Return a checked subtotal
UML and source walkthrough

SAY
Each group computes a fresh sum from its child queries. This block is the recursive part of Group::minutes. One uniform query handles both leaf durations and nested subtotals.

The comment states the one-contribution rule. Start this call with the additive identity, zero. Borrow each child owner without copying it. Ask the actual child type for its duration. Test the budget before performing the addition. Begin throwing a budget-overflow exception. Supply the budget error message. Close the rejection branch. Add this accepted child exactly once. Close the loop over children. Return this group subtotal to its caller. Close the recursive query.

total remains between zero and ten thousand throughout successful execution. Adding before checking or accepting a negative child result breaks the bound.

45. Uniform does not mean every action fits
Recall and transfer

SAY
A common mistake is to put every possible operation on the shared base because the pattern promises uniform use. Uniformity is useful only for operations whose meanings remain clear. Minutes has a natural answer for a Step and a Group. Add-child does not have a natural meaning for a Step, so a do-nothing implementation would hide a programming mistake. The chapter instead takes a finished child list during Group construction. If editing becomes necessary, give editing a separate design with ownership and cycle rules. The fact that two objects share a query does not mean they should share every command.

46. Depth and width create different risks
Recall and transfer

SAY
A large tree can be wide, deep, or both. A million direct leaf children create a long loop, but only a small number of nested calls. A million groups inside one another create a very deep call chain and can exhaust the stack. The chapter demonstrates a small trusted tree; it does not promise safe traversal of arbitrary untrusted input depth. A file parser that builds these objects should enforce a depth limit, or the query can be redesigned to use an explicit stack. Notice that validation belongs where the risky input enters. Timing a tiny example does not establish a bound for every tree shape.
