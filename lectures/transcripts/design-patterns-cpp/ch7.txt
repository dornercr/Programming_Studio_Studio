Problem and first design

2. One report needs only one function
Problem and first design

SAY
This first program serves exactly one requirement: render a valid count in the plain format. A single function makes the contract visible and keeps the implementation short. The function returns a string value, so the caller owns the returned characters. It throws before formatting a negative number because negativity is a report-domain error. There is no need yet for an abstract Writer or a family of Report classes. We will earn that separation by showing independent changes, rather than adding it in anticipation of every possible future request. Notice that a valid zero is accepted; absence of work is still a meaningful count.

Problem and first design

SAY

4. Separate meaning from punctuation
Problem and first design

SAY
We can now name the design. Bridge keeps two related families connected through a stable operation so that they can grow independently. In this chapter, CountReport and WarningReport decide the meaning of the field. Plain and Brackets decide how that field is written. Report stores a borrowed Writer connection, and each concrete report crosses that connection during render. With two reports and two writers, we have four supported pairings but do not need four combination classes. This is not a promise that every imaginable display can use the same tiny operation. Independence only holds while the shared field contract carries the data each supported format needs.

5. The contract we must preserve
Requirements and mechanism

SAY
Counts in plain text and brackets. Two report types share a Writer interface because report policy and field formatting change for different reasons. Constructors make each pairing explicit.

Support count and warning reports in both formats. Classify n > 5 as high; zero through five as normal. Reject negative counts before formatting.

Reports never change a writer or own its lifetime. Writers preserve the supplied name and numeric value. Validation happens before formatting. These are the rules that define a correct extension, even if it has the right C++ types. An enum-based formatter is simpler for a permanently closed set of formats. Templates fit compile-time selection; virtual writers fit objects selected while the program runs.

6. Two useful reports, two useful formats
Requirements and mechanism

SAY
A small inspection tool prints a count and also classifies that count. One screen wants count=6. Another wants [count:6]. The classification report calls counts above five high and all others normal. It must work in either format. Negative counts are invalid. Requirements now vary in two directions: what the report means, and how its fields are written.

The simplest first version returns a string directly from a function. That is a good solution when there is one meaning and one format. A second function can serve a second fixed report. The difficulty appears when both dimensions grow. If each combination has its own class, two report types and two formats need four combinations. Three types and four formats need twelve. The count is the product of the choices, not automatically an exponential function of one choice. What hurts is repeated policy and repeated formatting.

7. Locate the two decisions before drawing classes
Requirements and mechanism

SAY
Suppose the warning boundary changes from five to ten. In the combined design, each warning-format class must change. Suppose the bracket screen changes its separator. Every bracket-report class must change. That gives a concrete reason to separate the decisions. The boundary rule belongs with the report; punctuation belongs with the writer. Neither side should inspect the exact type on the other side.

A bridge is a stable connection between a high-level operation and a lower-level implementation that can vary independently. Here Report supplies the high-level render operation and borrows a Writer. CountReport and WarningReport decide which field name to send. Plain and Brackets implement Writer::field. The bridge is the writer_ reference. The two families can now grow without adding one class for every cross-product combination.

The pattern's traditional word abstraction means the high-level view offered to the caller. It does not require every high-level class to be an abstract C++ base class. Our Report is abstract because two report meanings already exist and both must be usable through the same contract. A single concrete report with a Writer member would still separate format from meaning when only one report is needed.

8. Trace data and control across the bridge
Requirements and mechanism

SAY
In main, plain and brackets are created before the report objects that borrow them. cp stores a reference to plain; cb stores a reference to brackets. Calling cb.render(6) enters CountReport. validate first rejects a negative value. The report then sends the label count and integer 6 to writer_.field. Virtual dispatch selects Brackets::field. It creates [count:6] and returns that string by value through the report to main.

WarningReport follows the same route but chooses its label first. The conditional expression n > 5 ? "high" : "normal" evaluates the condition, selects exactly one of the two strings, and initializes label. The question mark introduces the true result, and the colon separates it from the false result. This colon is different from the colon that begins a constructor initializer list or a range loop. Syntax takes its meaning from its surrounding statement.

The returned strings own their character storage. The label passed to field is a const reference, so field borrows the argument during the call. Neither writer keeps that reference afterward. writer_ is a longer-lived borrow stored inside Report. Those are different lifetime obligations: a call parameter need only stay valid for the call, while a stored reference must stay valid for later calls too.

9. What compilation guarantees and what it cannot
Requirements and mechanism

SAY
The compiler checks public inheritance, virtual signatures, and whether each concrete class implements the required operation. override catches a mismatch. protected makes writer_ and validate available to the derived reports while keeping them out of ordinary client code. The helper is static because it depends only on its argument and needs no Report object. Constructors initialize the reference before any render call can occur.

The compiler does not verify that a new Writer preserves the label and value faithfully. A writer could accidentally swap field names or drop a minus sign. That would still compile. The shared semantic contract is therefore essential: format the supplied name and integer without changing their meaning. The report checks the domain rule that counts cannot be negative. The generic writer is capable of formatting any integer, which makes it usable in other domains.

At execution the same report can use either writer selected during construction. Our design does not provide a setter to switch writer_ later; C++ references cannot be rebound. To change format, construct a new report borrowing another writer. This keeps ownership and configuration simple. An application needing live format changes could instead hold a non-owning pointer with an explicit non-null rule or own an interchangeable writer. That requirement has not appeared here, so its extra states are unnecessary.

10. When the split helps, and when it does not
Requirements and mechanism

SAY
A bridge gives independence only when the interface is stable and truthful. If field lacks data one format needs, reports may begin checking for special writers. That is a warning that the boundary is too narrow or the supposedly independent dimensions are actually linked. Improve the contract using a real use case, or accept a smaller set of supported combinations. Do not promise that every conceivable report will work with every renderer.

An enum and one formatting function may be smaller when the set of formats is fixed and tiny. A template can select a writer at compilation and may remove virtual calls, but it exposes more implementation to callers and moves the choice from runtime to build time. Neither alternative is inherently inferior. The reason for this bridge is the already demonstrated independent growth in report policy and presentation.

Bridge and Adapter can produce similar shapes in a diagram. Their motivations differ. An adapter repairs an existing disagreement between interfaces. A bridge deliberately separates dimensions that should evolve independently. When reviewing a change, ask what boundary is being protected. Add tests for each report's meaning and each format's text, plus a few combinations. That protects the separation more effectively than checking only class names.

11. The abstraction role is not C++ syntax
Mechanism in C++

SAY
The traditional pattern word abstraction means the useful high-level view, not automatically an abstract C++ class. Here Report happens to be abstract because several report meanings need the same render operation. A single concrete report holding a Writer could still separate meaning from formatting. This distinction matters in reviews: counting abstract classes is not evidence that a bridge exists. Look instead for independently changing decisions connected through a useful operation. Writer::field receives a name and a number because these are the stable pieces of information both current formats can display. It should not ask which concrete report made the request.

13. Two references, two lifetime duties
Mechanism in C++

SAY
The same ampersand can appear in two places with different practical obligations. The field parameter borrows a string only while that one function call is active. The writer_ member is stored in Report and may be used much later. Its source writer must therefore outlive all those report calls. In main, writers are constructed first, followed by reports, which gives the correct reverse destruction order. The reference also fixes the pairing during construction: assigning through a reference does not make it refer to another object. A runtime format switch would need a new report or a deliberately different connection design, with its own rules.

14. Syntax does not enforce semantic honesty
Mechanism in C++

SAY
The compiler provides several useful checks, but none can read the business requirement. Protected makes writer_ and validate available to derived reports while keeping them out of ordinary client code. Static on validate means it uses no particular Report object's data. The conditional expression in WarningReport evaluates n greater than five and selects high or normal; its colon separates the two possible results. Override catches a mismatched field or render signature. However, a writer that changes six to seven still satisfies the type signature. Tests must verify that formatting preserves data and that the report chooses the correct label on both sides of the threshold.

15. Add CSV by extending one side
Mechanism in C++

SAY
The extension asks for comma-separated output. The useful test of our design is whether this format can be added without changing either report's decision logic. Csv implements field and joins the supplied name, a comma, and the number. That is sufficient for the existing fixed labels, because count, high, and normal contain no comma or quote. Do not claim that the result is a complete CSV encoder for arbitrary text. If labels become user-controlled, quoting and escaping become new requirements. A clear boundary makes that change local, but a boundary cannot eliminate the need to define the new format contract.

41. Extension solution and design review
Practice and extension

SAY

45. Independence has a price and a limit
Recall and transfer

SAY
Bridge is useful because the number of combinations grows as the product of the two choices. Two reports and four formats create eight possible pairings. Separate families can avoid writing a dedicated class for every pairing, but the combination behavior still needs thought and testing. If a new format requires information that field does not carry, forcing it into the interface may create special cases or concrete-type checks. That is evidence to revisit the contract. Sometimes an enum and a small switch is clearer for a closed set. The design is successful when real changes remain local, not when the diagram contains more boxes.

46. Bridge and Adapter can look alike
Recall and transfer

SAY
Both designs can show one object forwarding a call to another. That shared shape does not settle their purpose. In Adapter, a useful old service and an established caller disagree about an interface or meaning. In Bridge, we intentionally put reporting and formatting behind a connection so each side can develop independently. A real system can even place an adapter on one side of a bridge. The useful review question is therefore what change this boundary protects against. Here, adding a writer should not duplicate report policy. That story identifies Bridge more clearly than simply noticing a reference member.
