Design Patterns in C++
Chapter 15: Iterator — positions, boundaries, and valid traversal
Dr. Charles Dorner

1. The report needs values, not the storage plan
Problem and first design

SAY
A measurement log contains four and nine. One report needs their sum; another is still examining the first reading. We could give both reports the whole vector. That is easy today, but each report could start depending on indexing, contiguous storage, or the ability to change the vector. If the log later uses chunks, those assumptions become obstacles. The needed behavior is smaller: ask whether traversal is finished, read one value, and advance. An iterator is a separate object that holds this traversal position. The chapter calls its teaching interface Cursor. First we will see why an ordinary vector loop is enough until storage independence becomes a real requirement.

Problem and first design

SAY

3. A single position cannot serve independent readers
Problem and first design

SAY
Imagine placing a current_index member directly in the measurement log and letting every report use it. The first report advances, and the second unexpectedly starts at nine instead of four. The data did not change; the reports accidentally shared their progress. That is the pressure for a separate position object. Each Cursor contains its own index while borrowing the same Readings owner. Copying a cursor copies the position, so advancing the copy leaves the original alone. This does not mean the data was copied. The design separates two kinds of state: values owned by the collection and progress owned by each traversal. That separation lets reports compose without resetting one another.

4. An in-range index can still belong to stale work
Problem and first design

SAY
This controlled model keeps a copied index rather than a standard vector iterator, so no invalid iterator is dereferenced. Before the append, index zero refers to four and the saved generation is two. After adding twelve, index zero is still within bounds and at still returns four. Yet the saved generation no longer matches. Under the chapter's chosen policy, the old traversal is stale because any successful append ends it. A bound check alone cannot enforce that rule. The word stale means an old view of a changed collection, not necessarily a missing element. Later we place the version comparison inside every public cursor operation so callers cannot forget it.

5. The contract we must preserve
Requirements and mechanism

SAY
A checked cursor over a readings log. Cursor stores only a borrowed owner, saved version, and index. Readings keeps its representation private and refuses copying or moving that could complicate its identity. Values are copied out.

Visit readings in insertion order and support independent positions. Make empty/end behavior explicit. Reject cursor operations after a successful append.

The owner must remain alive and in place while a cursor is used. A live cursor index is at most the number of readings. A version mismatch is rejected before data access. An end position is never read as an element. These are the rules that define a correct extension, even if it has the right C++ types. Expose a vector const_iterator if the public contract can depend on vector rules. Own a snapshot if scans must survive later edits or owner destruction. A snapshot gives stability in exchange for copying and storage costs.

6. The problem: callers need readings, not storage details
Requirements and mechanism

SAY
A measurement log stores a sequence of integer readings. A report must visit the readings in insertion order and compute their total. The simplest loop uses a vector directly, and that is often the best answer when the vector is already part of the public design. The new constraint is that reports should not depend on the storage layout. The log may later use chunks, a file cache, or a filtered view. Reports also need independent positions: one view may be examining the first reading while another has reached the second.

Giving every caller a reference to the internal vector exposes more than traversal. Callers can start depending on contiguous memory, indexing, and mutation details. Copying the entire vector into every report hides storage but can waste memory when readings are numerous. We need a small object that remembers a position and provides the next value without handing over the container. That object is an iterator. The teaching implementation calls it Cursor to emphasize its explicit done, read, and next operations.

7. Separate a collection from a position within it
Requirements and mechanism

SAY
Readings owns its vector and a version number. Cursor borrows the Readings object, stores the version seen at creation, and starts its own index at zero. The collection therefore holds data while each cursor holds traversal state. Copying a cursor copies its position and saved version but still refers to the same owner. Advancing the copy does not advance the original. In the example, one cursor moves to nine while an independent copy still reads four.

The nested class declaration places Cursor inside Readings as part of its interface. A nested class can access the enclosing class private members through an object; it does not carry an implicit enclosing object by magic. owner_ provides that actual object. const Readings& prevents the cursor from modifying the owner through that reference. It does not prevent other code from calling append on the original non-const collection. That distinction is why a read-only reference does not make a changing collection safe by itself.

8. An end position exists, but it is not an element
Requirements and mechanism

SAY
For two readings, legal traversal positions are index zero, index one, and index two as the end marker. done reports true at index two. There is no third reading to return. read calls vector.at, which checks the bound and throws std::out_of_range when asked for the end element. next also rejects an attempt to step beyond end. Empty collections begin at end, so the same loop works without a special branch in the report.

The report loop checks !scan.done before calling read. The exclamation mark means not: it enters the body only while the cursor is not at end. After reading, scan.next advances one position. read returns int by value, so the report receives an independent copy. An element reference could avoid copying a large object, but that reference would introduce its own invalidation and lifetime rules. A copied integer keeps this first traversal interface honest and small. The cursor still borrows the collection and must not outlive it.

9. A changed collection makes old cursors stale
Requirements and mechanism

SAY
Invalidation means that an operation has ended a cursor validity under its documented rules. This implementation chooses a strict policy: every successful append invalidates every existing cursor, even if the vector happened to have spare capacity. append first checks that the version counter can be increased without wrapping, then appends the value, then increases the version. If vector growth fails, neither the collection contents nor the version is committed by this append of an integer. A cursor compares its captured version with the current version before done, read, or next proceeds.

A stale cursor is different from a cursor at end. End is a valid position in an unchanged collection. Stale means the view no longer matches the collection generation, even if its numeric index remains within bounds. Merely using at would detect a bad index but would not detect a changed traversal contract. The program checks this difference by creating a cursor, appending twelve, and rejecting use of the old cursor. Version exhaustion is rejected instead of wrapping to an old number that might make a stale cursor look current.

10. A safety check cannot bring a dead owner back
Requirements and mechanism

SAY
The version check reads owner_.stamp_. If the Readings object has already been destroyed, even that first read would use a dangling reference. The check therefore protects against documented mutation while the owner is alive; it is not a general lifetime detector. main declares the collection first and all cursors later, so the collection outlives them. Copy and assignment of Readings are deleted in this example, and it has no implicit move operation. Its identity stays fixed while cursors borrow it.

Alternative designs make different promises. A snapshot cursor could own a copy of the values, remain valid after append, and cost more memory. A cursor holding shared ownership of an immutable collection can extend lifetime without copying its data. Standard-library containers already supply carefully specified iterators; use them when their contracts fit. This Cursor deliberately does not claim to model a standard C++ iterator category: it lacks operator*, operator++, comparison, and the related type information. It teaches the separation of traversal state from storage without pretending to work with every standard algorithm.

11. Choose traversal features from the reporting problem
Requirements and mechanism

SAY
A forward scan is enough for the total. The lab introduces a real new need: show the newest readings first. Its reverse cursor stores the number of elements still available and reads the element at remaining minus one. It checks for zero before subtracting, because size_t is unsigned and zero minus one would wrap to a huge value. Forward and reverse cursors follow the same version policy, so a caller does not need to guess which mutation rules apply.

The primary tests establish behavior for a small deterministic collection, an empty collection, independent positions, end access, end advancement, and stale access. They do not prove thread safety. Concurrent append and read without synchronization can create a data race; a version integer is not a lock. A real reporting subsystem should either prevent concurrent edits during a scan, take a stable snapshot, or define synchronization around both data and cursor checks. The traversal interface makes that choice easier to review, but cannot make it disappear.

12. A nested type still needs an actual owner
Mechanism in C++

SAY
Cursor is declared inside Readings, which makes it a nested class. That placement grants access to the enclosing class's private members, but it does not magically provide a particular Readings object. The owner_ reference supplies that object. The const in const Readings& prevents the cursor from modifying the owner through this reference. It does not stop other code from calling append on a non-const Readings. Cursor also stores the generation it saw at creation and its own index. The compiler checks access and const rules when building the program. It cannot know whether someone will append later, so comparing generations is a runtime responsibility.

13. End is a position, not a hidden last element
Mechanism in C++

SAY
With two readings, zero and one select values. Two is the valid end position and selects no value. This extra position lets a loop stop without special knowledge of the last element. An empty collection starts at end immediately. The chapter's loop tests not done before reading, then advances once. The exclamation mark negates the boolean result: enter only while not finished. read uses at, so reading end throws instead of accessing unchecked memory. next rejects another advance from end. These are explicit contracts of the teaching Cursor, not a claim that every library iterator permits the same operations or throws the same errors.

14. Commit the collection change before the new version
Mechanism in C++

SAY
The generation records successful collection changes. append first checks whether increasing the counter would exhaust its range. It then adds the integer to the vector, and only after success increases stamp_. If allocating more vector storage fails for this integer append, the contents and generation remain as they were. Incrementing first could invalidate cursors even though no append took place. Letting the counter wrap creates the opposite risk: an ancient cursor could accidentally match a repeated number. The strict policy does not depend on vector capacity. Even an append that uses spare memory makes all old cursors stale. That predictable rule is easier to explain than an accidental dependency on allocation behavior.

15. A version number cannot resurrect an owner
Mechanism in C++

SAY
validate compares two numbers, but one number lives inside owner_. If that object has died, even performing the safety check is already invalid. The version mechanism therefore checks mutation while the owner is alive; it is not a lifetime detector. In main, Readings is declared before the cursors so its lifetime extends beyond theirs. The class also rejects copying and assignment, which keeps its identity simple and suppresses an implicit move in this design. None of this makes concurrent reads and appends safe. Two threads still need a shared synchronization rule around the data and checks. A snapshot or immutable shared owner changes these guarantees, but also changes cost and ownership.

16. Reverse traversal needs a careful zero boundary
Mechanism in C++

SAY
The reverse extension answers a new reporting need: show the newest reading first. It stores how many elements remain. With three readings, remaining is three, so the first index is two; next reduces the count to two. At zero there is no next index to compute. size_t is unsigned, so zero minus one wraps to a very large value instead of becoming a useful negative index. The source therefore checks done before subtracting. This design is not just the forward loop written backward. Its state meaning differs, while lifetime, stale-generation checking, and end rejection stay consistent. Keeping those shared rules makes future reporting features easier to test and explain.

45. Custom Cursor or standard iterator?
Recall and transfer

SAY
The custom Cursor teaches independent traversal and a deliberately checked mutation policy. It does not implement the standard iterator operations, comparisons, and type information expected by ordinary standard-library algorithms. Naming something an iterator does not make it usable by every algorithm. If a vector is already the intended public representation, its existing iterators are usually the simpler choice. If a report must survive later appends, a copied snapshot may be more useful than rejecting stale access, at the cost of copied data. Shared immutable storage can reduce copying while extending lifetime. Compare these options by the report's consistency and ownership needs before judging their syntax.

46. Three failures need three different tests
Recall and transfer

SAY
Do not collapse every traversal failure into out of range. At end, the owner is alive and unchanged, but no element occupies the current position. A stale cursor may still have index zero, yet its generation contract has ended. A dangling cursor has no valid owner to inspect and must be prevented by design, not demonstrated by executing undefined behavior. The chapter tests empty input, independent positions, end reads, end advancement, and mutation rejection. When adding reverse traversal, repeat the contract tests for that direction rather than checking only the printed reverse order. A sequence that prints twelve, nine, four can still mishandle empty input or wrap after the last element.
