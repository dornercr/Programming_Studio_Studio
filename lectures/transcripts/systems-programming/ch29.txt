1. Find the eligible set before searching for a block
Problem and first experiment

SAY
A cache does not usually let every block occupy every slot. In a set-associative model, an address selects one set and the block may use one of that set’s ways. Two ways means two possible positions inside each set, not two sets total. Keeping these quantities separate prevents incorrect capacity and indexing calculations. The block is the transferred unit of data; a cache line stores a resident block together with identifying state. We will calculate geometry first, then examine why a matching tag alone is not enough to call an access a hit. These are explicit modulo-indexed models, not universal hardware layouts.

3. A tag is meaningful only in a valid resident line
Problem and first experiment

SAY
A newly created cache model may initialize every numeric tag to zero. That does not mean block zero is already loaded. The line needs a validity state that distinguishes an empty slot from a resident tag whose value happens to be zero. Otherwise the first request for block zero becomes a false hit. The distinction resembles optional values elsewhere in the course: absence and ordinary content are different facts. Real cache metadata can include dirty and coherence state too. Our basic read model isolates validity and tag matching, so it does not establish whether a write already holds the required coherence permission.

4. Search every eligible way and require validity
Problem and first experiment

SAY
The two-way set begins with one invalid entry whose stored tag is zero and one valid entry holding tag one. A naive comparison against the first stored tag prints true for zero, but the correct search prints false because that entry is invalid. Searching for one returns true from the second way. This demonstrates both requirements: inspect all eligible ways and ignore invalid entries. The function borrows the fixed array and does not modify it, so no replacement policy is involved yet. A miss would require a separate decision about which way to fill or evict. Matching logic and replacement are distinct parts of cache organization.

8. Chapter 29 — Cache Organization
Systems mechanisms and source lecture

SAY
A cache stores copies of blocks from a larger addressable space. Its organization determines where a block may reside and how hardware recognizes whether the requested block is present. The following models use byte addresses and power-of-two sizes to make the arithmetic transparent. Real processors add details such as physical or virtual indexing choices, coherence states, replacement approximations, and multiple cache levels. Use the simplified models to understand mapping and conflicts, not to infer every detail of a particular CPU from a virtual address alone. [ R3 ]

10. Cache blocks
Systems mechanisms and source lecture

SAY
A block is the fixed-size unit transferred between levels in the model. If blocks contain 64 bytes, addresses 0 through 63 belong to block 0, and addresses 64 through 127 belong to block 1. The block number is address / block_size , rounded down. The within-block offset selects the requested byte after the correct block has been found. Fetching a block can benefit later accesses to any of its bytes.

In plain English: A cache is like keeping the things you use most often on your desk instead of walking to a storage room every time.

11. Cache lines
Systems mechanisms and source lecture

SAY
A cache line is the cache storage associated with one block’s data and its identifying state. Informal usage often treats “block” and “line” as interchangeable, but distinguishing the transferred block from its cache-resident slot can clarify replacement. A line contains metadata as well as data: a tag, validity information, and potentially dirty and coherence state. Capacity specifications usually refer to data capacity rather than including every metadata bit.

12. Cache slots
Systems mechanisms and source lecture

SAY
A slot is a possible resident location for a block. A direct-mapped cache gives each block exactly one eligible slot. More associative organizations give a block several or all slots as candidates. Replacement selects among eligible resident lines, not among arbitrary locations that the indexing rule forbids. This distinction is why unused capacity in one set does not necessarily help a different set that is experiencing conflicts.

In plain English: A cache is like keeping the things you use most often on your desk instead of walking to a storage room every time.

13. Cache sets
Systems mechanisms and source lecture

SAY
A set groups the eligible slots for a mapping. If a cache has S sets and E ways per set, it has S*E data-line slots. A block maps to one set and can occupy one of that set’s ways. A two-way cache does not mean two sets. It means two eligible line positions within each set. Keep set count, associativity, and line size separate when calculating capacity.

In plain English: A cache is like keeping the things you use most often on your desk instead of walking to a storage room every time.

14. Tags
Systems mechanisms and source lecture

SAY
A tag identifies which of the many blocks mapping to a set occupies a particular valid line. After selecting the set, the cache compares the requested tag with the valid resident tags. A tag match without a valid line is not a hit. Other state can affect whether a request can proceed, especially for writes in a coherent system. The basic read-only model tracks validity and tag identity.

16. Direct-mapped caches
Systems mechanisms and source lecture

SAY
A direct-mapped cache has one way per set. Lookup and replacement are simple because each block has one possible location. Two frequently used blocks that map to the same set can repeatedly evict each other even when other sets are empty. This behavior is a conflict, not a shortage of total line slots alone. Changing layout, padding, or associativity can alter the conflict pattern. Whether such a change helps an actual application must be measured under the real cache organization.

In plain English: A cache is like keeping the things you use most often on your desk instead of walking to a storage room every time.

17. Set-associative caches
Systems mechanisms and source lecture

SAY
An E -way set-associative cache permits up to E resident blocks in each set. Associativity reduces some conflicts at the cost of more lookup and replacement complexity. It does not eliminate capacity limits or every conflict pattern. For example, a two-way set repeatedly accessed by three mutually conflicting blocks can still thrash under LRU. More ways help only when the increased flexibility retains useful blocks that would otherwise be displaced.

In plain English: A cache is like keeping the things you use most often on your desk instead of walking to a storage room every time.

18. Fully associative caches
Systems mechanisms and source lecture

SAY
A fully associative cache allows a block to occupy any line slot. In the model, it has one set and as many ways as resident lines. This removes set-index conflicts but leaves finite capacity and replacement decisions. Fully associative models are useful reference points for classifying misses. They are not automatically practical implementations for large, low-latency hardware caches because searching and maintaining many candidate entries has costs.

19. Decomposing an address
Systems mechanisms and source lecture

SAY
Assume a 32-KiB data cache, 64-byte lines, and eight ways. The set count is: There are 6 offset bits and 6 set-index bits. For address 0x1234 , the offset is 0x34 (52), the set is 0x08 (8), and the tag is 0x1 . The block number is 0x48 , or 72; 72 mod 64 = 8 . Address 0x2234 has the same offset and set but tag 2. The two addresses can coexist in different ways of the same set. In a direct-mapped cache with the same 64 sets and line size, they would compete for one line position. Notice that holding set count fixed while changing associativity also changes total capacity; fair comparisons must state which dimensions remain fixed.

In plain English: Think of an address written on a note: the note can tell you where to look, but it does not prove the thing is still there or that you are allowed to use it.

25. Direct mapping is one way per set
Reason about the implementation

SAY
With four sets and one way, blocks zero and four both map to set zero. Alternating between them can cause repeated misses even if sets one, two, and three remain unused. The trouble is restricted placement, not necessarily insufficient total capacity. A two-way version might retain both in set zero, while a different layout could map the data to different sets. Neither change is automatically faster on a real machine because lookup cost and other workload details also matter. First identify the model’s eligible positions, then explain the collision before proposing a fix.

26. Bit extraction follows from power-of-two geometry
Reason about the implementation

SAY
For sixteen-byte lines, four low bits form the line offset. With four sets, the next two bits select the set. The remaining high bits identify the tag under this simple model. Division and remainder express the same decomposition for these powers of two. But actual cache indexing can include more complex functions, and a generic numeric exercise may use positive sizes that are not powers of two. State the geometry and indexing assumption before drawing bit fields. A mask copied from a four-set example will not correctly describe an eight-set model merely because both use the same integer address type.

27. Associativity reduces some conflicts but not all misses
Reason about the implementation

SAY
Increasing ways gives each block more eligible resident positions, but it does not create unlimited storage. Three blocks repeatedly targeting a two-way set can still evict useful entries. A fully associative model removes set-index restrictions by permitting any line slot, yet it still has finite capacity and must choose a victim when full. This distinction is useful when reviewing an optimization claim: more associativity can reduce placement conflicts, but it cannot keep an arbitrarily large working set resident. Real hardware also pays for more complex tag lookup and replacement bookkeeping. Explain the access trace and capacity before predicting a benefit.

28. Lookup does not decide how a miss changes state
Reason about the implementation

SAY
Our tag-search program returns a Boolean and leaves its set unchanged. That is a lookup operation. A complete cache model also needs to fill a missing block and decide which eligible line to replace. Mixing these stages can hide bugs: code may update a tag before recording whether the access was a hit, causing every request to appear successful. Compute the observation from the old state, then update according to the policy. In maintenance tests, verify both the returned result and the resulting resident state. A correct index formula alone does not establish that the next access will behave correctly.

44. Configuration checks protect the formulas
Recall and transfer

SAY
A configurable decomposition function receives geometry as data, so it cannot assume that every input was chosen by a textbook author. Division by zero is invalid, and inconsistent capacity, line size, and associativity can produce a meaningless organization. The source lab rejects zero line size and zero set count before division.
