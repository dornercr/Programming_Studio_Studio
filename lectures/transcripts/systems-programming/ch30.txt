1. A hit rate belongs to a trace and an initial state
Problem and first experiment

SAY
A cache trace is a story about changing state. An access may find a resident line, or it may bring a new block in and displace another. Starting cold is a specific assumption: no requested block is initially present. Starting with the final state of an earlier run can change the very first event. Therefore, a percentage without the access sequence and initial condition is incomplete evidence. We will separate rate arithmetic from state simulation, then compare the same trace under two placement rules. Both models are deterministic and useful for reasoning; neither measures elapsed cycles on a real processor.

2. Keep local and global denominators separate
Problem and first experiment

SAY
The program prints three rates from explicit counts. One hundred of one thousand original accesses miss L1, giving ten percent. Twenty of the one hundred requests reaching L2 miss there, giving a local L2 rate of twenty percent. Those same twenty are only two percent of the original one thousand. The difference is the denominator, not contradictory data. Multiplying ten percent by twenty percent gives the global two percent; adding them would be wrong. These are supplied counts in an arithmetic example, not collected hardware events. A real report should state whether its counters include all original accesses or only requests reaching one level.

3. A compulsory miss depends on the stated reference model
Problem and first experiment

SAY
In a cold model with no prefetch, the first request for a block must obtain it. That is a compulsory miss. The same numeric address is not forever labeled compulsory: a later request may hit, or it may miss after eviction for a different reason. Prefetching adds another distinction because data can arrive before its first demand access. The transfer still happened, but the first demand need not be a miss. Always state the initial state and whether the model includes prefetch. Otherwise two correct traces can appear to disagree simply because they answer different questions about when the block became resident.

4. Compare a conflict against equal-capacity flexible placement
Problem and first experiment

SAY
The trace is block zero, block two, block zero, block two. In the two-slot direct-mapped model, both blocks select slot zero and keep evicting each other, so all four accesses miss. The fully associative reference also holds only two blocks, but it may place them in either slot. Its first two accesses miss and its final two hit. The output therefore reports zero direct hits and two reference hits. This comparison supports a conflict explanation for the repeated misses, not a total-capacity shortage. We use block numbers directly here, not byte addresses, and the list maintains most-recently-used order for the reference policy.

10. Cache hit
Systems mechanisms and source lecture

SAY
A hit occurs when the requested block is present in a usable cache entry. The model can satisfy the access at that level. A hit does not imply zero cost; lookup, data delivery, dependencies, and other execution constraints remain. For writes in a coherent machine, a resident line may still require permission acquisition or coordination. The simple examples in this chapter use reads so that tag residency is sufficient to classify a hit.

In plain English: A cache is like keeping the things you use most often on your desk instead of walking to a storage room every time.

11. Cache miss
Systems mechanisms and source lecture

SAY
A miss occurs when the consulted cache cannot satisfy the request from a usable resident entry. The system obtains the block from another source, potentially another cache, another core, or memory, depending on the hierarchy and coherence state. The cost is not necessarily a full trip to DRAM. An L1 miss that hits in L2 differs from a last-level miss. State which cache level is being discussed and whether a miss rate is local to that level or relative to all original accesses.

In plain English: A cache is like keeping the things you use most often on your desk instead of walking to a storage room every time.

12. Hit rate
Systems mechanisms and source lecture

SAY
Hit rate is hits divided by accesses for the stated cache and interval. If 90 of 100 accesses hit, the rate is 90%. A cold-start interval can have a lower rate than steady state even when the repeated workload is unchanged. Aggregate hit rate can conceal expensive phases or uneven requests. A large number of cheap hits does not necessarily compensate for a small number of extremely costly misses on a critical dependency chain.

13. Miss rate
Systems mechanisms and source lecture

SAY
Miss rate is misses divided by accesses. In the simple model where each access is exactly one hit or miss, it equals 1 - hit_rate . Multilevel rates require careful denominators: an L2 local miss rate counts misses among requests that reached L2. If L1 misses on 10% of original accesses and L2 misses on 20% of those, then 2% of original accesses miss both levels. Adding 10% and 20% would be the wrong calculation.

14. Compulsory misses
Systems mechanisms and source lecture

SAY
A compulsory miss is the first access to a block in a cold-cache reference model. The block has not yet been brought into the cache by a prior access in that model. Larger lines can reduce the number of distinct blocks for a sequential region but can also fetch unused bytes. Prefetching changes when a block is brought in and how demand misses are observed. It does not make data transfer disappear. When classifying misses, state whether the model includes prefetching and what initial cache state is assumed.

15. Capacity misses
Systems mechanisms and source lecture

SAY
A capacity miss occurs because the useful working set exceeds the cache’s available storage under the chosen reference model. Even a fully associative cache of the same capacity cannot retain everything needed across the reuse interval. The common three-category classification compares behavior against a fully associative reference cache with a specified replacement policy, often LRU. Classification depends on that reference. It is not a universal label attached permanently to an address.

16. Conflict misses
Systems mechanisms and source lecture

SAY
A conflict miss arises from restricted placement in sets when a fully associative reference cache of the same capacity would have retained the block. Repeated collisions can cause misses even when the total active block count is no greater than cache capacity. The compulsory/capacity/conflict model is useful but incomplete for coherent multiprocessors. Invalidations, sharing, prefetch interactions, and other effects can introduce additional causes. Do not force every hardware event into a three-category model that deliberately excludes those mechanisms.

Reason about the implementation

SAY
Now imagine a two-line fully associative LRU reference visiting blocks zero, one, two, then zero. The first three are new blocks. Installing two evicts zero under LRU, so the final zero misses even without set restrictions. That supports a capacity-related classification under this stated reference. 24. Observe the old state before installing the new block
Reason about the implementation

SAY
The source lab uses optional values for slots. An empty optional means no block is resident, while a present optional can hold any unsigned block number, including zero. For each access, the function checks that old state first, then installs the requested block in the selected slot. Reversing these steps would make the new block appear to match itself and inflate the hit count. Other slots retain their state. The vector is local to the function, so each call starts cold by contract. If a later feature preserves the vector across calls, that intentionally changes the initial-state policy and needs new tests.

25. A hit avoids some work, not all work
Reason about the implementation

SAY
A cache hit is not an operation that takes zero time. The processor still performs lookup, obtains the data, and uses it according to instruction dependencies. A long chain of dependent hits can limit progress even with a high hit rate. For writes on a coherent machine, a resident line may also require permission changes or communication before the store can proceed. The chapter’s simple model uses reads so residency and tag identity are enough for classification. Do not silently apply its hit definition to every write scenario. Name the operation and the modeled state before translating a hit count into a performance claim.

26. A percentage needs a cost model before it predicts time
Reason about the implementation

SAY
Suppose ninety-six percent of accesses hit. That percentage alone does not tell us whether the remaining four percent hit in the next cache, wait on main memory, overlap with other work, or stall a serial dependency chain. An average-cost formula must state its hit cost, miss penalty, and assumptions about overlap. Even then it is a model, not a substitute for a measurement under the actual workload. Report the exact counts as well as percentages for small traces: two hits among six accesses is easier to audit than a rounded thirty-three-point-three percent without its denominator.

42. Warm-state tests belong beside cold-state tests
Recall and transfer

SAY
The source hit-count helper deliberately creates a fresh slot vector on every call. Two calls with the same inputs therefore repeat the same cold trace. A persistent cache object would instead retain the final state until reset. Both APIs are reasonable, but they answer different questions. Tests should make that policy visible rather than relying on hidden static storage. For a persistent version, verify one cold pass, an immediate warm pass, and a pass after reset. When a benchmark warms up before measurement, document that too. Otherwise a performance comparison may merely compare different starting states rather than different implementations.

43. Explain every miss before optimizing the count
Recall and transfer

SAY
Begin with one unexpected miss and reconstruct the preceding state. Was the block never brought in, evicted because of restricted placement, or absent even in the same-capacity reference? Did invalidation or prefetching change the story? Only after identifying the cause should you propose padding, tiling, more capacity, or another policy.
