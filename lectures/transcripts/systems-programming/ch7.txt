1. A usable pointer needs more than a nonzero address
Problem and first experiment

SAY
A pointer can be non-null and still be unsafe to dereference. It may name an object whose lifetime ended, an out-of-range position, unsuitable alignment, or storage that does not contain the required kind of object. Concurrent conflicting access adds another condition. The operating system checking whether a page is mapped does not establish all these object-level facts. Two small arrays can occupy one writable page while writing past the first array remains invalid. This chapter treats pointer reasoning as object reasoning. Before following the arrow, name its target, owner, valid range, access type, and allowed interval of use.

2. One-past is a stopping position, not a final element
Problem and first experiment

SAY
For a three-element array, begin points to element zero and end may be formed as begin plus three. The end position is useful because a loop stops when its cursor reaches it. There is no fourth element to read there. This half-open range convention represents an empty range naturally when begin equals end. Pointer subtraction within the same array measures elements, not bytes, provided the difference is representable. Do not first compute a wildly out-of-range pointer and hope to validate it afterward. Check an index or remaining count before forming the pointer. The order of the check is part of keeping the program within defined behavior.

3. Two access paths can share one object without sharing every value
Problem and first experiment

SAY
The address-of operator gives both pointer variables access to the same live integer. Writing nine through first changes that object, so reading through second prints nine. Next we copy the integer into snapshot. Writing twelve through first still changes the shared target, but it does not revisit the old value already copied into snapshot. The remaining lines print nine and twelve. This is valid aliasing: two permitted access paths reach one object. The demonstration does not involve ownership transfer, pointer arithmetic, or concurrent access. It isolates why a copied pointer and a copied pointed-to value are different things when tracing a real function's effects.

4. Reacquire an element after a reallocating operation
Problem and first experiment

SAY
The vector begins with four and eight. We save index one and copy its current value, eight. reserve requests more than the present capacity, which requires reallocation if it succeeds. Any earlier pointers, references, or iterators to elements would be invalid afterward. This program deliberately uses none. It appends twelve, then obtains a fresh pointer through at using the saved index. Both the saved and reacquired values print eight, and the size prints three. 10. Addresses versus pointers
Systems mechanisms and source lecture

SAY
An address is a location identifier. A pointer is a language value used to designate an object, function, or permitted boundary position. Implementations commonly represent object pointers as virtual addresses, but the language attaches rules that are not captured by the displayed number alone. For example, two allocations may reuse the same numeric address at different times. A stale pointer to the first allocation does not become a valid owner of the second merely because the bits match. Similarly, converting a pointer to an integer for logging does not grant permission to perform arbitrary integer arithmetic and convert the result back. Use pointer-producing operations that preserve the intended object relationship.

In plain English: Think of an address written on a note: the note can tell you where to look, but it does not prove the thing is still there or that you are allowed to use it.

11. Dereferencing
Systems mechanisms and source lecture

SAY
A dereference is valid only when the designated access is valid. Ask five questions: Is the target alive? Is it within the permitted range? Is it correctly aligned? Does the access type match the object’s allowed interpretation? Is the access properly synchronized with conflicting operations? A hardware page permission check answers only part of this list. A use-after-free can access a page that is still mapped and writable. An out-of-bounds write can remain within the same mapped page. The operating system protects address-space regions, while the language and program design must protect object boundaries and lifetimes inside those regions.

12. Pointer arithmetic
Systems mechanisms and source lecture

SAY
For a pointer into an array, adding an integer moves in units of the pointed-to type. If p points to a[2] , then p + 3 points to a[5] when that position is within the permitted array range. Subtracting two pointers into the same array yields an element count, not a byte count, provided the difference is representable in ptrdiff_t . Do not form a wildly out-of-range pointer and then compare it with an end pointer. Validate an index against the remaining element count before computing the pointer. A one-past pointer is permitted as a boundary marker but not as an element. It is a useful sentinel precisely because the traversal stops before dereferencing it.

In plain English: Think of an address written on a note: the note can tell you where to look, but it does not prove the thing is still there or that you are allowed to use it.

13. Arrays and pointers
Systems mechanisms and source lecture

SAY
An array often converts to a pointer to its first element, but the conversion loses extent information. A function parameter written int values[] is adjusted to an int* parameter; it does not carry the caller’s array length. The callee needs a separate count or a range abstraction. An array of pointers is also different from a pointer to an array. int* rows[3] contains three pointer objects. int (*row)[4] points to a four-integer array. These declarations produce different scaling and memory access. Draw the objects and arrows when syntax becomes confusing: the picture should show actual pointer objects separately from the integer storage they designate.

14. Iterators
Systems mechanisms and source lecture

SAY
An iterator generalizes traversal over a sequence. Some iterators are ordinary pointers; others hold more complex state. An iterator and an end sentinel describe a range whose validity depends on the owning container and on operations that may invalidate positions. A vector reallocation invalidates pointers, references, and iterators to its elements. Inserting into other containers has different rules. Do not generalize one container’s behavior to another. A range-based loop can still be invalidated by changes made inside the loop. The abstraction removes repetitive syntax, not the need to respect lifetime and invalidation rules.

15. Pointer comparisons
Systems mechanisms and source lecture

SAY
Equality comparisons can test whether pointers designate the same relevant position or are null, subject to language details. Relational ordering and subtraction are much more constrained. Comparing positions within one array is meaningful; using built-in relational operators as a portable ordering for arbitrary unrelated allocations is not a sound general technique. In C++, std::less for pointer types provides a strict total ordering suitable for ordered containers when such ordering is needed. That ordering is not a statement that two objects are adjacent or belong to one allocation. An ordered pointer map does not authorize arithmetic across its keys.

In plain English: Think of an address written on a note: the note can tell you where to look, but it does not prove the thing is still there or that you are allowed to use it.

16. Pointer validity
Systems mechanisms and source lecture

SAY
Pointer validity is a property maintained by program structure. An owner keeps storage alive; borrowers use it only within an agreed interval. A mutation that reallocates storage ends the validity of old element pointers even if the container itself remains alive. Represent these rules in interfaces. A function that retains a pointer should say so. A returned view should identify the owner whose lifetime supports it. A callback should not outlive its context. Nulling one pointer after release helps avoid accidental reuse through that variable, but it does not update other aliases. Ownership discipline prevents the error earlier than a last-minute null check.

In plain English: Think of an address written on a note: the note can tell you where to look, but it does not prove the thing is still there or that you are allowed to use it.

17. Aliasing
Systems mechanisms and source lecture

SAY
Aliasing occurs when multiple expressions can access the same storage. Aliasing can be intentional, as when two pointers refer to the same integer. The compiler must preserve required behavior for permitted aliases, but type-based access rules allow it to assume that certain unrelated typed accesses do not designate the same object. Casting an int* to float* and reading through it is not a portable representation conversion. Use byte access or a suitable copy operation. In C++, char , unsigned char , and std::byte have designated representation-inspection roles; do not assume every small integer type has the same privilege. Aliasing also affects optimization: a store through one pointer may force a reload through another unless non-aliasing can be established. [ R7 , R8 ]

18. A bounded cursor
Systems mechanisms and source lecture

SAY
The requirement is to read a two-byte big-endian field from a byte sequence without advancing past its end. Model the state as a span of remaining bytes. A successful operation consumes exactly two bytes; failure consumes none. Companion listing: ch07/cursor.cpp Initially the range length is three. The first check passes, and 0x12 × 256 + 0x34 = 4660 . The cursor then becomes a one-byte range. The second check fails before any indexing, leaving that range unchanged. The final output is 4660 1 . The design’s key property is transactional cursor movement: validation and decoding occur before the state change. An alternative that increments the pointer after reading the first byte can leave the parser half-consumed on failure. Keeping the cursor unchanged makes recovery or higher-level error reporting much easier.

20. Recognizing an aliasing hazard
Systems mechanisms and source lecture

SAY
If two pointers can refer to the same integer, storing through one may change what a later load through the other must observe. A compiler cannot freely reuse an old loaded value unless the language’s aliasing rules prove the pointers independent. When optimization depends on non-aliasing, express that contract using the mechanisms supported by the language and implementation rather than assuming the compiler will infer it.

24. A cursor should consume nothing when a field is incomplete
Reason about the implementation

SAY
A parser reading a two-byte field needs both bytes before it can promise success. If it advances after reading only the first byte and then discovers the second is missing, failure leaves the cursor half-consumed. That makes retry or higher-level error reporting harder. The chapter uses a remaining-range view so the operation can check size, decode the value, and only then replace the cursor with its suffix. Success consumes exactly two bytes; failure consumes none. This is a small transaction boundary. It separates temporary reasoning from committed state and gives callers a clear rule for composing several field readers.

25. Ordering pointers does not put their allocations in one array
Reason about the implementation

SAY
Pointers into one array can be compared as positions and subtracted under the language's rules. Pointers to unrelated allocations do not gain that relationship just because their displayed addresses look close. When an ordered container needs an ordering over pointer keys, std::less supplies the relevant ordering facility. That ordering still does not say the objects are adjacent or permit subtraction across allocations. This distinction matters in allocators, where physical-neighbor metadata must be based on the managed region rather than an arbitrary sorted list of pointers. Keep the purpose of a comparison explicit: identity, range position, or key ordering are different questions.

26. Invalidation is an event in the owner’s history
Reason about the implementation

SAY
A vector can remain a perfectly valid container while a capacity-changing operation invalidates all old element pointers. The owner's lifetime therefore supplies only part of the borrowing contract. The permitted mutation interval matters too. Similar rules apply to callbacks retaining context pointers and views into resizable buffers. Setting one local pointer to null after release does not rewrite other aliases stored elsewhere. A maintainable API should document whether a view remains valid across growth, removal, reset, or replacement. If long-lived identity is required, consider stable ownership or explicit handles rather than trying to make raw pointers survive operations that invalidate them.

27. A cast changes the access expression, not the stored object
Reason about the implementation

SAY
Our first demonstration used two int pointers to the same int, so the aliasing was permitted and the later read had to observe the write. Casting an int pointer to a float pointer and reading through it is a different claim: it asks the language to treat the storage as an unrelated typed object without establishing that object. That is not a general conversion of the integer's numeric value or a portable inspection technique. Use ordinary numeric conversion for values, and suitable byte access or bit_cast under its constraints for representation tasks. Clear intent lets both maintainers and the optimizer rely on the same valid access rules.

A half-open range stops before its end iterator. For an empty vector, begin equals end, so no dereference occurs. The const reference prevents this function from resizing the vector. 43. Test ranges at the boundary without crossing it
Recall and transfer

SAY
For a range algorithm, an empty case is not optional decoration. It tests whether the implementation dereferences before checking the stopping condition. A single-element range tests whether the final increment and termination agree. A parser should exercise every input length around the required field size and verify the remaining range after success and failure. The tests themselves must not inspect an invalid pointer to see what happens. Instead, verify the guard and the state it preserves. Tools can help catch mistakes during development, but a clean run is evidence for tested paths, not a proof that every possible borrow and mutation ordering is safe.
