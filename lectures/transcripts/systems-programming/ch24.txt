1. A mapping must answer where and whether
Problem and first experiment

SAY
A table that returns a frame number but ignores access rights is not a complete protection model. Reading, writing, and fetching an instruction can require different permissions. A page-table entry therefore carries control information as well as location information. At one level it may point to another table; at a leaf it may describe the mapped page. The exact encoding belongs to the architecture and configuration, not to a guessed C++ struct layout. Our added programs use explicit small fields to explain decomposition and combined checks. They neither read nor modify the operating system’s active page tables.

2. Split a tiny address into two indexes and an offset
Problem and first experiment

SAY

3. A missing entry can have several meanings
Problem and first experiment

SAY
An absent entry stops the current hardware translation path, but it does not say what recovery is allowed. A valid anonymous region may need a zero-filled page. A valid file mapping may need file data that is already cached or must be read. An address outside every permitted region should be rejected. Treating every absence as permission to allocate would turn invalid accesses into silently accepted memory. The chapter separates the present indicator from the kernel’s policy metadata for this reason. When debugging a fault, identify the mapping policy and requested operation before assuming the device or disk is involved.

10. Page-table entries
Systems mechanisms and source lecture

SAY
A page-table entry encodes mapping information and control bits. Depending on its level and configuration, it can point to another table or describe a mapped page. It may include a physical address, presence information, access permissions, and status used by memory-management policy. An entry is not a portable C structure whose bit layout can be guessed from a diagram for another architecture. Kernel code must follow the architecture’s encoding and required update procedures. Ordinary user programs should reason about the behavior exposed by mapping APIs instead of attempting to manipulate active page tables.

In plain English: The program uses a map of memory addresses. The operating system translates that map to where the data is actually stored.

11. Present bit
Systems mechanisms and source lecture

SAY
A present indicator tells hardware whether an entry is valid for the corresponding translation step. An absent entry can cause a page fault. The kernel may use nonpresent encodings and its own metadata to remember whether the region is demand-paged, swapped, invalid, or associated with another policy. Therefore, “not present” does not automatically mean “read this page from disk.” The handler must first establish that the access is legitimate. A zero-filled anonymous page may require no file read at all. A completely invalid address must not be repaired by granting access merely because a fault occurred.

12. Writable bit
Systems mechanisms and source lecture

SAY
A writable permission controls whether stores are allowed under the architecture’s access rules. A mapping can be readable without being writable. Copy-on-write commonly uses a temporarily nonwritable hardware mapping for a region that is logically permitted to become privately writable after a fault. Permission interpretation can involve multiple levels and processor controls. It is unsafe to inspect only one leaf bit and conclude that an access must succeed. The complete translation and protection state determines the result. This chapter’s exercises state a simplified combined-permission rule explicitly.

13. User-accessible bit
Systems mechanisms and source lecture

SAY
A user/supervisor permission distinguishes mappings accessible to user-mode code from mappings reserved for privileged access. It helps prevent an application from treating kernel data as ordinary user memory even when some related address range exists in the broader translation structure. This hardware distinction does not replace file permissions, process credentials, or application authorization. A user-accessible buffer may still contain data that an application should not disclose to a particular network client. Memory-access enforcement and application-level information policy operate at different layers.

14. Multilevel page tables
Systems mechanisms and source lecture

SAY
A multilevel design divides the virtual page number into several indexes. Each index selects an entry in the current table; that entry leads to the next level until a mapping is found. Large-page entries can terminate a walk earlier when the architecture supports them. A familiar x86-64 example uses four levels with 9 index bits per level and a 12-bit offset, describing a 48-bit virtual-address organization subject to canonical-address rules. Other configurations can add a fifth level and expand the address width. The exact layout is a platform fact, not a consequence of the C++ pointer type alone. [ R3 , R10 ]

In plain English: The program uses a map of memory addresses. The operating system translates that map to where the data is actually stored.

15. Page-table walks
Systems mechanisms and source lecture

SAY
A page-table walk follows the hierarchy to resolve a translation. Hardware performs walks on the reference architecture, potentially using internal caches for table information. The naive count of one ordinary memory access per level is a useful upper-level teaching model but not a complete performance prediction. A walk can stop because it finds a valid leaf mapping, encounters an absent entry, or detects a protection problem. Once a translation is cached in a TLB, later accesses can avoid repeating the full walk until the entry is evicted or invalidated. The next chapter separates translation caching from data caching.

In plain English: The program uses a map of memory addresses. The operating system translates that map to where the data is actually stored.

16. Memory protection
Systems mechanisms and source lecture

SAY
Protection checks combine the requested operation with the applicable mapping permissions and architectural state. Reading data, writing data, and fetching instructions are not necessarily governed by identical permissions. Non-executable mappings help separate data storage from executable code. Changing a page-table entry is not enough when processors retain cached translations based on the old state. The system must perform the required invalidation and coordination. On a multicore system, other cores may also hold relevant translations; this is the reason for translation invalidation mechanisms often discussed as TLB shootdowns.

17. A two-level address decomposition
Systems mechanisms and source lecture

SAY
Use a 16-bit teaching address space with 256-byte pages and two levels of 16-entry tables. The address fields are: Address 0xABCD yields outer index 0xA , inner index 0xB , and offset 0xCD . Suppose outer entry A points to a valid inner table and inner entry B maps frame 0x34 . The translated address is 0x34CD in a physical model that supports that frame number. Now add permissions. The outer entry allows user reads and writes, but the inner entry allows only user reads. A user load succeeds; a user store fails. For this model, effective permissions are the intersection of the permissions along the path. Giving the outer entry more authority cannot override a restrictive leaf entry. A flat table for all 256 virtual pages needs 256 entries. The two-level arrangement needs one 16-entry outer table plus 16 entries for each allocated inner table. With only one populated inner table, it uses 32 entries; with all 16 inner tables allocated, it uses 272 entries. Hierarchy saves space for sparse mappings but is not automatically smaller for a fully populated tiny address space.

In plain English: Think of an address written on a note: the note can tell you where to look, but it does not prove the thing is still there or that you are allowed to use it.

23. Sparse mappings motivate multiple table levels
Reason about the implementation

SAY
Imagine a large virtual space where a process uses only a few separated regions. A flat table would reserve a slot for every virtual page even across unused gaps. A hierarchy groups pages under intermediate entries, allowing an unused group to have no allocated lower-level table. This trades some lookup structure for reduced metadata in sparse cases. The tradeoff is not a promise that all page-table walks cost one fixed number of memory loads. Hardware can cache intermediate information and support large-page leaves that end a walk early. Explain both why the hierarchy exists and which caches may hide some of its cost.

24. User permission and application authorization are different
Reason about the implementation

SAY
Suppose a server stores two clients’ records in the same user-accessible heap. Hardware allows the server’s thread to read those bytes. That permission does not authorize sending one client’s record to another client. Page-table user permissions separate execution privilege domains; the application still enforces account and data-access policy. Conversely, a correct account check cannot make a supervisor-only mapping readable from user mode. These are different boundaries with different evidence. In a review, name the subject of each permission: processor privilege, process credentials, or authenticated application identity. Calling all three access control without distinction makes debugging and security reasoning imprecise.

25. Execute permission applies to instruction fetch
Reason about the implementation

SAY
A page can hold bytes that are readable as data without being permitted as instructions. This distinction supports separating writable storage from executable code. Do not model every operation with one Boolean called allowed and then assume the same result applies to reads, writes, and execution. Instead identify the requested access and combine the relevant permissions. Our short lab intentionally models only reads and writes, so it does not prove an execution policy. If instruction fetch is added, give it an explicit access kind and tests. This makes the omission visible and prevents a future feature from silently inheriting the wrong permission meaning.

26. Changing the table does not erase cached translations
Reason about the implementation

SAY
Suppose the kernel changes a mapping from writable to read-only. If a processor still uses a cached translation with the older writable permission, merely updating memory does not complete the intended revocation. The architecture supplies invalidation mechanisms, and the kernel coordinates them with relevant processors and mapping changes. This is why table updates require a protocol, not just a store to a struct field. Our models omit actual translation caches unless explicitly introduced. When interpreting their output, remember that a successful model lookup cannot verify real invalidation ordering. The next chapter adds cached translation state so this dependency becomes visible.

43. Describe a walk as a sequence of justified steps
Recall and transfer

SAY
To explain a page-table walk, begin with the address model rather than a memorized number of levels. Extract the next index, inspect that entry, and determine whether it is present, a pointer to another level, or an allowed leaf. Carry applicable permission restrictions forward. At the end, combine the selected frame with the original offset only if the requested operation is permitted. An absent or restrictive step changes the result. This reasoning transfers from our two-level exercise to more complex architectures without pretending their encodings match. A strong explanation identifies what was checked, not merely that the walk eventually found a number.
