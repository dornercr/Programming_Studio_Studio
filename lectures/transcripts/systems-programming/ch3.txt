1. Bits give possibilities; a format gives meaning
Problem and first experiment

SAY
Four independent positions with two choices each give sixteen possible patterns. That arithmetic does not tell us whether a pattern means a count, a permission set, or a reserved state. For example, 1010 is ten under an unsigned interpretation, but a format might use it as two separate flags and a small mode field. A debugger can display the same storage in binary, hexadecimal, or decimal without changing it. Begin a bit-level problem by naming the interpretation and numbering the positions. Only then can we judge whether a mask or shift performs the required operation. The representation is concrete; its application meaning is a separate contract.

2. A numeral is a notation, not a sequence of digit bytes
Problem and first experiment

SAY
Hexadecimal 2D contains two times sixteen plus thirteen, giving forty-five. Its binary form is 0010 1101, since each hexadecimal digit maps to four bit positions. Writing that numeric literal in source does not mean memory stores the character codes for 2 and D. A text representation is a different object with an encoding and a length. This distinction matters in parsers and binary files: converting a displayed number back to a value is not the same operation as copying an integer's bytes. Choose binary when positions matter, hex when grouped patterns matter, and decimal when a human count is the clearest view.

3. Some required bits is not all required bits
Problem and first experiment

SAY
The required mask has bits three and two set, while flags has only bit two. Bitwise AND keeps that common bit, so any is true. The intersection is not the entire required mask, so all is false. Logical AND asks a different question: are both integer operands nonzero? They are, so logical and also prints true, even though one required permission bit is missing. 10. Bits
Systems mechanisms and source lecture

SAY
A bit is a binary digit with two possible values, conventionally zero and one. A group of w bits has 2^w possible patterns. Four bits have 16 patterns; eight bits have 256. The number of patterns follows from independent choices: each new position doubles the number of combinations. Physical devices need not store literal written zeros and ones. They distinguish states that are interpreted as those values. Software normally reasons above that physical level. What matters to the program is the behavior promised by the storage and instruction interfaces, including whether a read or write is atomic for the particular object and access. A bit pattern is an ordered collection of bits. If bits are numbered from the least significant position, bit i contributes a weight of 2^i to an unsigned interpretation. The pattern 10110110 therefore represents 128 + 32 + 16 + 4 + 2 = 182 when treated as an unsigned eight-bit value. The pattern itself has not changed if another interpretation calls it a negative signed number. This distinction explains why a debugger can show the same storage in several formats. A display format is a lens on the stored representation. It does not alter the bytes or prove that the chosen interpretation matches the program’s intended type. Boolean operations combine truth values. AND is true when both inputs are true. OR is true when at least one is true. XOR is true when the inputs differ. NOT reverses a truth value. Applied independently to corresponding bit positions, these operations become bitwise operations on a word. Logical operators such as && and || are not substitutes for bitwise & and | . Logical operators convert operands to truth values and short-circuit evaluation. Bitwise operators operate on integral representations after the applicable promotions. x && y asks whether both are nonzero; x & y preserves positions where both patterns have a one.

11. Bytes
Systems mechanisms and source lecture

SAY
In a byte-addressable machine, consecutive addresses identify consecutive bytes. A four-byte integer occupies four such positions. A machine may transfer a wider quantity in one operation, but the address still names its starting byte. The reference x86-64 platform uses eight-bit bytes. Byte addressability does not guarantee that every byte address is valid or equally efficient for every access width. A page may be unmapped, an address may not meet a type’s alignment, or an access may cross a cache-line boundary. Keep addressing granularity separate from access permission, required alignment, and transfer granularity. An address is usually written as a hexadecimal number because hexadecimal groups bits neatly. Increasing an address by one moves one byte in the reference machine. Increasing a typed pointer by one moves one element, which may occupy several bytes. Confusing those two increments is a common source of incorrect offset calculations. Addresses are meaningful within a context. A process address space, a device’s bus address space, and a file offset are not interchangeable even when their numeric values fit in the same integer type. Label the address domain in interfaces and diagnostic output. A correct number in the wrong domain still points to the wrong place. An object’s representation is the sequence of bytes used to store it. Some bits carry value information; others may be padding. Character-type access and suitable byte-copy operations allow representation inspection without pretending that an unrelated typed object exists in that storage. Representation inspection is not serialization. A raw structure dump can include padding, host byte order, pointers, and implementation-specific layouts. It may also disclose bytes the application never intended to publish. Define external formats field by field, with explicit sizes and byte order, and decode into ordinary language objects after validating the input.

12. Number Bases
Systems mechanisms and source lecture

SAY
Binary uses base two. Each position has twice the weight of the position to its right. 110101 means 1 × 32 + 1 × 16 + 0 × 8 + 1 × 4 + 0 × 2 + 1 × 1 , giving 53. Leading zeroes change the displayed width but not the unsigned value. Binary notation makes masks and bit fields visible, but it becomes long for addresses and large integers. Use it when the positions themselves are the subject of the explanation. When only the value matters, decimal or hexadecimal may be easier to read. Decimal uses base ten. The number 347 means 3 × 100 + 4 × 10 + 7 . Decimal is convenient for human counts and measurements, but it does not reveal power-of-two boundaries as clearly as binary or hexadecimal. A numeral is a notation for a value, not a storage format. Writing 255 in source does not mean the executable stores the three character bytes '2' , '5' , and '5' . A numeric literal is translated as a value; a string literal is a sequence of character-code units. Distinguish these when designing parsers or examining file contents. Hexadecimal uses base sixteen, with digits 0 through 9 and A through F . One hexadecimal digit represents exactly four bits. Thus 0xB6 corresponds to 1011 0110 . Two hex digits describe an eight-bit byte without the visual length of eight binary digits. Hexadecimal is especially useful for alignment and field boundaries. An address ending in a hexadecimal zero is divisible by sixteen. Clearing the lowest hexadecimal digit rounds down to a sixteen-byte boundary. This visual rule works because sixteen is a power of two, not because hexadecimal has a special relationship with memory beyond its notation. To convert an unsigned binary or hexadecimal numeral to decimal, sum each digit multiplied by its positional weight. To convert a nonnegative decimal integer to another base, repeatedly divide by that base and collect remainders from last to first. For 182 in base sixteen, 182 = 11 × 16 + 6 , so the digits are B6 . For fractional values, positions to the right of the point use negative powers of the base. Binary 0.101 equals 1/2 + 0/4 + 1/8 = 0.625 . A finite decimal fraction need not have a finite binary expansion. That fact will explain many floating-point surprises in Chapter 5.

13. Bitwise Operations
Systems mechanisms and source lecture

SAY
Bitwise AND, written & , retains a one only where both operands have one. It is commonly used to test or extract fields. If flags & mask is zero, none of the masked bits are set. If the requirement is that all masked bits are set, test (flags & mask) == mask instead. These two predicates are different. With mask 0b1100 and flags 0b0100 , “any” is true but “all” is false. A permission check that confuses them can authorize an operation based on only part of the required state. Name helper functions according to the exact predicate they implement. Bitwise OR, written | , sets a bit when either input has it set. flags |= mask turns on the selected bits while leaving other positions unchanged. It does not toggle them: applying the same OR operation twice has the same result as applying it once. This idempotence is useful for accumulating capabilities or marking completed phases. It is not automatically thread-safe. Two ordinary read-modify-write expressions on a shared word can race even when they set different bits. Use an atomic operation or a lock when multiple threads update the same shared object. Bitwise XOR, written ^ , sets a bit when the input bits differ. flags ^= mask toggles selected positions. XORing with the same mask twice restores the original pattern because each selected bit is flipped twice. XOR can also compare patterns: a ^ b marks their differing positions. It does not provide cryptographic security by itself. A repeated fixed XOR mask is a reversible encoding, not a secure encryption design. In systems code, use XOR for clearly defined bit manipulation rather than as an unexplained clever trick. Bitwise NOT, written ~ , flips every bit in the promoted operand type. That last phrase matters: applying ~ to a small integer type often first promotes it to int . The result may therefore have a wider type than the original byte. To clear selected bits in a word, use word &= ~mask with a mask of a suitable unsigned word type. When displaying or storing a smaller result, perform the intended conversion explicitly. Do not assume that a unary operator preserves the width of an eight-bit input merely because the variable was declared as a byte. A left shift moves bits toward more significant positions and fills low positions with zero. For unsigned values, it corresponds to multiplication by a power of two with reduction to the result type’s width. The shift count must be nonnegative and smaller than the width of the promoted left operand. Use unsigned types for field manipulation. The signed rules differ across language versions, and mathematical multiplication may overflow even when a target instruction happens to discard high bits. A shift by the full width is not a portable way to create zero. Handle full-width masks as an explicit special case. [ R36 ] For unsigned values, right shift fills high positions with zero and corresponds to division by a power of two with the fractional part discarded. It is the natural operation for moving a field down to bit zero before masking it. C17 leaves the right shift of a negative signed integer implementation-defined. C++20 specifies the signed result consistently with rounding division by a power of two toward negative infinity. This differs from signed integer / , which truncates toward zero. To avoid accidental dependence on these distinctions in binary formats, decode fields into unsigned values first. [ R8 , R36 ] A mask is a pattern that selects positions. A single-bit mask at position k can be formed as a correctly typed unsigned one shifted by k , after checking the count. A low- n -bit mask is often written (1u << n) - 1 , but that expression fails when n reaches the type width. Define the allowed field width and position before constructing a mask. For a 32-bit word, require width <= 32 , position <= 32 , and width <= 32 - position . The subtraction form avoids overflow in position + width . Handle width zero and width 32 deliberately. To extract a field of width w beginning at bit p , shift the word right by p , then AND with a low- w -bit mask. In notation, field = (word >> p) & mask . The result is right-justified and independent of unrelated high bits. For word = 0xB6 , p = 2 , and w = 3 , the shifted value is 0x2D ; masking with 0x07 yields 5. The selected bits are positions 4, 3, and 2, read as 101 . Write down the numbering convention before tracing; formats sometimes number bits in a different direction. Insertion has two separate operations: clear the destination field, then OR in the new field value. Merely ORing the new value leaves old one-bits in place. The usual expression is (word & ~shifted_mask) | ((value & mask) << position) for a validated nonempty field. Masking the incoming value truncates it. That may be the intended policy, but protocol encoders often should reject a value that does not fit instead. Silent truncation can hide invalid input. Decide whether the operation is a bit-level replacement or a validated semantic assignment, then make that decision visible in its interface.

14. Updating one packed field
Systems mechanisms and source lecture

SAY
The requirement is to replace the three-bit field at positions 2 through 4 in 0xB6 with the value 3, while preserving every other bit. Companion listing: ch03/fields.c First, low is 0x07 , and shifting it left twice produces mask = 0x1C . Clearing that mask from 0xB6 produces 0xA2 . Shifting the new field, 3, left twice produces 0x0C . ORing 0xA2 and 0x0C yields 0xAE . The program reports old=5 new=0xAE . Verification should also check preservation: (next & ~mask) == (word & ~mask) . This proves that the example did not change any unselected bit. If the clear step is removed, old ones remain and the result becomes 0xBE , not the requested replacement. That controlled failure shows why “set bits” and “replace a field” are different operations.

20. Width rules apply after integer promotion
Reason about the implementation

SAY
A variable described as a byte does not guarantee that every expression involving it stays byte-wide. Small integer operands can be promoted before a bitwise operation. In particular, complement may produce a wider result than the original object suggests. Shifts also have requirements: the count must be nonnegative and less than the width of the promoted left operand. Shifting by the full width is not a portable shortcut for zero. A reusable field helper should state its word type, allowed positions, and allowed widths, then handle special cases explicitly. These rules matter during source-level reasoning even if one machine instruction happens to mask its shift count.

21. Idempotent setting is different from toggling
Reason about the implementation

SAY
An operation is idempotent when repeating it has the same effect as doing it once. Setting a ready flag with OR has that property: once the bit is one, another identical OR leaves it one. XOR does something different. It toggles selected bits, so repeating the same toggle returns them to their previous values. This difference matters when a message might be retried. A repeated set-ready operation can preserve the intended state, while a repeated toggle-ready operation can undo it. Neither expression by itself supplies concurrency safety for a shared ordinary integer. The update policy and the synchronization policy are separate parts of the contract.

22. Byte access does not erase object boundaries
Reason about the implementation

SAY
On the reference platform, increasing a byte address by one moves one eight-bit byte. Increasing an int pointer by one moves one int element, typically several bytes on that platform. The arithmetic units differ. More importantly, neither view grants access beyond the live object or range. A page can be mapped while a particular array index is still invalid. Character and byte access can inspect object representations under the language rules, but raw representation is not automatically a stable file format. Keep the address domain, extent, and interpretation beside the operation. A correct number used as the wrong kind of offset can still reach the wrong place.

23. Decide whether an oversized field is rejected or truncated
Reason about the implementation

SAY
A three-bit field can represent values from zero through seven. If a setter receives nine and masks it with seven, the inserted field becomes one. That may be a useful low-bit operation, but it is not a faithful assignment of the requested mode nine. A protocol encoder often should reject the request instead. State the policy before selecting the expression. A low-bit extraction helper and a checked semantic setter can legitimately behave differently because they promise different things. Tests should include seven, eight, and nine, not only ordinary values below the limit. That boundary makes silent information loss visible during maintenance.
